## 四、当前文档体系的正确使用方式

- `./算子目录.json`：正式全量清单的机器读入口，适合前端、工具链和自动化校验。
- `./算子目录.md`：正式全量清单的人读入口，适合快速查看分类分布与索引。
- `./算子名片/`：逐算子的输入、输出、参数、运行时附加输出、适用场景与限制入口。
- `./算子手册.md`：总览、概念、连线、案例与最佳实践手册，当前定位为“总览与使用手册”，不再承担全量清单职责。
- `../../operators/`：英文路径兼容镜像，已同步当前名片内容，供旧链接继续访问。
- `./测量类算子精度升级说明-2026-04.md`：近期测量类精度升级的专项说明，适合研发、测试和验收评审引用。

## 五、本轮已完成与后续边界

本轮已完成：

- 代码侧正式算子数量、目录清单、名片清单、手册口径和 legacy 文档入口的全量比对。
- 156 张正式算子名片按当前元数据重刷参数表、输入端口表、输出端口表。
- 名片补充算法说明、实现策略、核心 API 调用链、运行时附加输出、性能特征、证据与失败契约、适用场景和已知限制。
- `docs/operators/` 已同步为当前 160 个名片/索引文件。
- `quality/evals/reports/operator_quality_matrix.md` 重新生成到 156 行，并修正 `Convert.ToDouble` 被误判为 TODO 的生成器问题。

仍需后续专项推进：

- `FrameChangeTrigger` 已进入正式目录和名片；2026-05-20 已补齐 contract、dataset 与 field-substitute replay 证据，后续维持回归即可。
- 质量矩阵中仍有大量算子缺 dataset、field replay 或真实产线签核证据；这属于证据治理问题，不应仅通过文档措辞关闭。
- 外部沟通时，public dataset、semi-synthetic、field-substitute replay 仍不能写成真实产线签核。

## 六、维护建议

- 新增算子时，优先保证 `OperatorMetaAttribute`、输入输出端口和参数元数据完整，再生成目录与名片。
- 外部沟通时，正式算子总数统一使用 **156**，不要把 legacy alias 计入产品能力口径。
- 如果需要做“工业级验收材料”，建议在全量目录基础上，按模块追加专项说明文档，而不是继续把所有内容堆入手册。
