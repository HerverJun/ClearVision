# ClearVision 开发规则

> 最后更新：2026-07-05
> 规则版本：v2.0

## 规则 1：代码与文档入口同步

旧 active 待办总表路径已不再存在，不要新增或继续引用该路径。当前文档体系以 `docs/进行中/`、`docs/归档/` 和文档治理标准为准。

### 当前文档事实源

- 项目文档入口：`docs/README.md`、`docs/导航.md`
- 当前计划入口：`docs/进行中/当前计划/README.md`
- 新排查和未闭环事项：`docs/进行中/未闭环事项/README.md`
- 待复核结论：`docs/进行中/待复核/索引.md`
- 文档治理标准：`docs/参考资料/规范/文档治理标准.md`
- 归档入口：`docs/归档/README.md`

### 适用范围

- 代码、配置、项目结构、脚本或 CI 修改。
- API、运行时契约、算子行为、Station 同步、部署方式、质量 gate 或用户工作流变化。
- 文档入口、计划、审计、发布说明或长期规范变化。

### 执行步骤

#### 1. 修改前

- 查看 `docs/README.md` 或 `docs/导航.md`，确认本次变更所属文档域。
- 若变更属于当前计划，优先从 `docs/进行中/当前计划/README.md` 找到唯一 active 入口。
- 若只是新发现的问题或风险，记录到 `docs/进行中/未闭环事项/` 或 `docs/进行中/待复核/`，不要直接塞进旧计划。

#### 2. 修改后

- 更新受影响的 active 计划、未闭环事项、审计清单或长期规范。
- 若计划已完成或被替代，新增闭环说明后迁入 `docs/归档/已关闭事项/` 或 `docs/归档/过期计划/`。
- 若代码变更不需要文档更新，在交付说明中写明原因，例如“仅内部测试桩调整，无用户或契约变化”。

#### 3. 更新内容要求

需要更新的内容通常包括：

1. 当前状态或最近更新。
2. 完成项和验证证据。
3. 未完成项、阻塞项或后续入口。
4. 受影响的接口、配置、脚本或运行方式。
5. 归档、替代或废弃说明。

### 变更记录格式

```markdown
### YYYY-MM-DD 更新（简短描述）
- [修改类型] 具体修改内容
- 完成：已完成的任务或修复
- 进行中：仍在推进的事项
- 阻塞：需要用户、现场或外部系统确认的问题
- 验证：实际运行的命令、测试或人工检查
```

### 修改类型标记

- 完成：已完成的功能、任务或闭环项。
- 进行中：正在开发或复核的功能。
- 阻塞：遇到问题，需要额外输入或外部状态变化。
- 文档：文档更新。
- 配置：配置文件、脚本或 CI 调整。
- 修复：Bug 修复。
- 新增：新增功能或能力。

### 检查清单

交付或提交前确认：

- 代码修改已完成并通过相应验证。
- 相关文档入口仍能从 `docs/README.md` 或 `docs/导航.md` 找到。
- active 计划、未闭环事项或审计清单已同步更新。
- 已完成事项有验证证据，未完成事项有后续入口。
- 没有新增对旧 active 待办总表路径的引用。

## 规则 2：保持代码与文档同步

### 代码注释规范

- 公共 API、跨模块契约和复杂生命周期逻辑应有 XML 文档注释或清晰行内说明。
- 注释解释意图、边界和风险，不复述显而易见的语句。
- 并发、取消、资源释放、ImageWrapper 生命周期、Station 同步和持久化恢复逻辑需要写清楚维护约束。

### 文档同步规范

- 用户可见行为变化：更新用户说明、README、运行手册或导航入口。
- 开发者契约变化：更新架构、runtime、frontend、engineering 或 operator-library 文档。
- 测试与质量流程变化：更新质量 gate、证据规范或对应审计记录。
- 历史结论不直接改写；如需更正，新增当前说明并链接旧材料。

## 规则 3：定期回顾

### 每日回顾

- 检查本日变更是否需要同步 active 计划、未闭环事项或审计清单。
- 确认下一步入口清晰，不留下只存在于对话里的任务。

### 每周回顾

- 复核 `docs/进行中/当前计划/README.md` 是否仍是唯一当前计划入口。
- 将已闭环事项迁入归档，保留完成项、验证方式、遗留边界和后续入口。
- 清理过时路径引用，特别是旧 active 目录、旧算子目录镜像和历史计划入口。
