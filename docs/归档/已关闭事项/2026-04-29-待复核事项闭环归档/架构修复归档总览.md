# 架构修复归档总览

## 归档结论

架构修复主体按“工程实现项”口径关闭，已经不再是线序检测当前阻塞项。

现有仓库信号显示，以下主干能力已基本落地：

- 运行时生命周期由 `Coordinator + Worker` 收口
- 事件链路已从单点 WebMessage 收口到 `SSE + EventBus + fallback`
- 节点预览与诊断链路已经进入主路径

## 已关闭范围

- `InspectionRuntimeCoordinator + InspectionWorker` 生命周期主干
- `IInspectionEventBus + InMemoryEventStore + InspectionEventEndpoints` 事件链路
- SSE 优先、WebMessage fallback 的反馈路径
- `PreviewNodeEndpoints` 节点预览路径
- `PreviewMetricsAnalyzer / AutoTuneService / AutoTuneEndpoints` 工程框架

## 拆分边界

不再挂在本待复核项下的内容：

- 真实样本验证、70 张样本实验与 McNemar 统计检验
- 线序专用 preview / autotune 契约
- AI follow-up 参数边界
- 生产模型、标签资产与现场数据可用性

## 与线序检测的关系

对线序检测来说，架构修复不是当前第一阻塞项。

当前真正阻塞线序落地的，是：

- 模型 / 标签资产可用性
- 线序专用 preview / autotune 契约
- AI follow-up 的参数边界

这些内容原本指向旧 active 文档：

- `docs/active/线序检测闭环下一步清单.md` 当前工作区未保留，见 [`旧计划缺失引用说明`](../../过期计划/旧计划缺失引用说明.md)。

如果后续要推进真实样本验证，应新建场景专项或质量/field replay 专项文档，而不是重新打开本架构修复归档项。
