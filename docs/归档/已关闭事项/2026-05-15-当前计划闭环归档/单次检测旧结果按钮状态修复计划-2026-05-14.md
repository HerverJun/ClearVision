# 单次检测旧结果按钮状态修复计划

## 背景

本计划针对检测界面排查中发现的次要风险：单次检测按钮进入运行态后，前端主要依赖 `inspectionController.onInspectionCompleted` 回调恢复按钮状态。如果回调中的结果被 `InspectionPanel.handleInspectionResult` 判定为其他工程的旧结果并提前返回，面板不会执行 `setButtonsState(false)`，可能导致“单次运行”按钮保持禁用，直到刷新界面或其他状态路径覆盖。

当前相关链路：

- `inspectionPanel.js`：`handleRunSingle()` 启动时调用 `setButtonsState(true)`。
- `inspectionController.js`：`executeSingle()` 完成后调用 `handleInspectionCompleted()` 并通知完成回调。
- `inspectionPanel.js`：`handleInspectionResult()` 在工程 ID 不匹配时提前 `return`，该分支不会恢复按钮。

## 目标

- 单次检测请求结束后，无论结果是否被当前面板接收展示，都能可靠恢复单次/连续/停止按钮状态。
- 保留跨工程旧结果保护，避免旧结果污染当前工程的统计、状态、图像和分析卡片。
- 不改变连续检测的按钮语义：连续检测运行中仍保持运行按钮禁用，停止按钮可用。

## 范围

纳入范围：

- `InspectionPanel.handleRunSingle()` 的成功、失败、无回调、重复结果、旧结果等状态恢复策略。
- `InspectionPanel.handleInspectionResult()` 旧结果分支的状态处理边界。
- `inspectionController` 完成回调去重导致面板未收到回调时的兜底处理。
- 前端单元或轻量 DOM 测试，以及必要的 E2E smoke 场景。

不纳入范围：

- 相机软件触发、回车光电触发、连续采集等后端拍照逻辑。
- `InspectionService`、`ImageAcquisitionService`、相机 SDK 调用顺序。
- 检测结果判定规则和历史结果持久化格式。

## 风险判断

风险等级：中。

触发条件不是主路径，但一旦触发会表现为按钮灰住，用户容易误判为相机或检测服务卡死。更麻烦的是，它属于 UI 状态一致性问题，后端可能已经结束请求，单看服务日志未必能直接定位。

## 修复方案

### 方案 A：单次运行使用 `finally` 兜底恢复

在 `handleRunSingle()` 中记录本次是否为单次运行，并在 `await inspectionController.executeSingle()` 后进入 `finally`。如果当前不是连续运行，则调用 `setButtonsState(false)`。这样即使完成回调因旧结果或去重未执行，按钮仍能恢复。

要点：

- `try` 前设置本地标记，例如 `const wasContinuous = this.isContinuous === true`。
- `finally` 中仅对非连续模式恢复按钮，避免误停连续检测。
- 成功路径仍允许 `handleInspectionResult()` 更新状态、统计和分析卡片。
- 如果 `executeSingle()` 返回错误结果而不是抛异常，也应恢复按钮。

### 方案 B：旧结果分支只跳过展示，不阻断运行状态恢复

在 `handleInspectionResult()` 的工程 ID 不匹配分支中，保留“不要更新统计/图像/分析卡片”的保护，但在返回前根据当前运行模式恢复按钮：

- 如果 `this.isContinuous` 为 `false`，执行 `setButtonsState(false)`。
- 更新保护提示为“已忽略其他工程结果”或保持当前提示，不强行改成 OK/NG。
- 不增加计数，不写最近结果，不更新状态灯为检测结论。

方案 A 是主要兜底，方案 B 是更贴近风险点的局部修正。建议两者同时做：A 保证单次请求生命周期正确，B 保证旧结果分支行为自洽。

### 方案 C：补一个请求序列号，减少旧回调误伤

如果后续仍出现竞态，可以在 `InspectionPanel` 内维护 `singleRunRequestId`：

- 单次启动时递增请求 ID。
- 结果回调只处理当前请求 ID 或当前工程结果。
- `finally` 仅恢复自己启动的那次单次运行，避免多个入口同时触发时互相覆盖。

该方案可作为二阶段增强，不作为首轮必做。

## 回滚策略

本修复应只改前端状态管理，不改后端检测和相机链路。若上线后出现按钮状态异常，可回滚 `inspectionPanel.js` 中的本次状态恢复改动；检测执行接口和相机配置不受影响。

## 备注

本计划不处理“软件触发来源为回车光电触发时，按钮等待外部 Enter 信号”的主问题。该行为属于当前配置语义，和本计划中的旧结果状态恢复风险分开跟踪。
