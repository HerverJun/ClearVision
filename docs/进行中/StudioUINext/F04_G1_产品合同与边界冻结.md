## 1. 代码事实摘要

- `StudioUI/src/app/router.ts` 只有 `requiresSession`、`internal`、`workspaceMode` 元数据，没有 `beforeEach` 认证/授权执行。
- 当前 `sessionProjectionOwner` 只读 `GET /api/auth/me` 并轮询投影；它不是 Auth lifecycle state machine，也不写 token。
- StudioUI 只在 `studioPlatform.ts` 读取 sessionStorage 的 `cv_auth_token`；当前生产源码没有 `setItem/removeItem` token writer。
- `apiTransport.ts` 是唯一直接 `fetch` 基础设施；正式写端口只有 Workspace Save、Preview、Formal Run 三组 F03 owner。
- Project 写端点使用 `CanEditProject=Admin|Engineer`；Project GET、Results、Preview 与 Formal Run 当前只受全局 authenticated middleware 保护。
- `WorkspaceCapabilityEnabled=false` 与 `StudioUiEnabled=false` 仍是正式默认值。
- frontend hidden/disabled 只是产品呈现，不构成后端授权。

## 4. Route guard contract（G2 实现输入）

| 类别 | 冻结合同 |
| --- | --- |
| Public routes | 仅 `/login`、`/setup` 与 host bootstrap diagnostic；业务页面不是 public |
| Setup route | 先读 `GET auth/setup-status`；仅 `requiresSetup=true` 可进入；完成后禁止返回 setup |
| Login route | 已有有效 session 时重定向 safe return 或 `/overview`；登录成功后 token 只由唯一 owner 写入 |
| Protected routes | 所有 ProductLayout route 必须验证 session；当前 `requiresSession` 只是元数据，不是实现 |
| Role-restricted routes | Workspace、Diagnostics 以及 profile 限制 route 在 navigation 与直接 URL 两处使用同一 policy projection；后端仍是最终授权 |
| Internal routes | Labs 仅内部 profile/browser fixture；正式 product profile 直接 URL 拒绝 |
| Forbidden | authenticated 但 role/profile 不允许时进入内部 `/forbidden`；不泄漏敏感详情 |
| Not found | 未匹配内部路径进入 404；未认证时先登录，不以 404 绕过 session |
| Safe return | 只接受解析后同 origin、hash-router 内、allowlisted product route；拒绝 scheme、`//`、反斜杠、encoded separator、`..`、Labs、login/setup/forbidden 自循环 |
| Browser back | 不得恢复已失效 token 下的 protected DOM；guard 重新评估 session generation |
| Logout | 先请求 server logout；无论响应结果均清除本地 token 投影、递增 generation、dispose protected owners，再进入 login；unknown response 不保留可用 session |
| Invalid redirect | 丢弃并回 `/overview`；不得把外部 URL 传给 `location.assign` 或 router |

G2 必须让 `authLifecycleOwner` 吸收或替换 `sessionProjectionOwner`，成为唯一 auth/session 状态机与唯一 token writer。G1 不创建空壳 owner。

## 8. Project contract decision register（G3A 输入，不在 G1 实现）

### D-PROJECT-01 Create idempotency

- 当前事实：`POST /api/projects` 直接 `ProjectService.CreateAsync`，请求没有 client operation identity；响应丢失后重试会创建重复工程。
- 风险：重复 Project、重复 assets/flow、用户无法判断 outcome。
- 候选：A 名称查重；B `Idempotency-Key/clientRequestId` + server operation record；C client 生成 ProjectId。
- 推荐：B。Next 创建必须携 UUID `clientRequestId`；同 identity 同 payload replay 返回同一 Project，不同 payload 返回 409。
- 待批准合同：扩展 `POST /api/projects` request；首次 201、replay 200 + replay marker；增加受控 create-operation reconcile read 或等价查询。
- Permission：`CanEditProject`。Revision：新建响应 revision 0。Reconcile：按 clientRequestId，不按名称。Backward compatibility：legacy 可暂时省略 identity，Next 不可省略。
- 测试草案：lost response/retry、same-key different payload、并发双提交、权限、restart replay。

### D-PROJECT-02 Create partial success

- 当前事实：先 `_projectRepository.AddAsync(project)`，再独立写 flow JSON；flow 写失败可能留下已创建 Project。
- 风险：201 未返回但 Project 已存在、Flow 缺失、清理不可证明。
- 候选：A catch 后删除补偿；B 把 create 纳入 `ProjectSaveCoordinator` staged commit；C 接受 partial 并返回 operation state。
- 推荐：B，必要时辅以可恢复 create operation record；不得由前端拼接补偿。
- 待批准合同：Application Service 的 atomic/staged create；response 包含 project identity/revision 与 completion status。
- Permission：`CanEditProject`。Revision：仅完整 commit 后发布 revision 0。Reconcile：D-PROJECT-01 identity。Backward compatibility：保持 `POST /projects` 路由。
- 测试草案：repo success/flow failure、flow success/repo failure、进程重启 recovery、无孤儿 assets。

### D-PROJECT-03 Delete revision and cleanup semantics

- 当前事实：`DELETE /projects/{id}` 无 expected revision；先 soft-delete repository，再删 session/flow/assets，清理失败会抛错但 Project 已删除。
- 风险：删除 stale Project、partial cleanup、lost response 后盲重试、结果历史处置不明确。
- 候选：A 保持无 revision；B `If-Match`/expected revision + deletion receipt + cleanup state；C 新建第二 delete endpoint。
- 推荐：B，保留唯一 DELETE route；禁止 C。结果历史默认保留并保持 projectId identity，除非另行批准 retention policy。
- 待批准合同：DELETE 携 expected revision/operation identity；200 deletion receipt（projectId、deletedRevision、cleanupStatus、operationId），409 stale/running；受控 reconcile read。
- Permission：`CanEditProject`。Revision：必须匹配当前 PersistenceRevision。Reconcile：operationId/clientRequestId。Backward compatibility：legacy 无 revision 仅在过渡期，需显式弃用策略。
- 测试草案：stale/running、每个 cleanup 故障点、lost response、重复 delete、结果历史保留。

### D-PROJECT-04 Not-found/error mapping

- 当前事实：GET detail 返回 404；update/delete 的 `ProjectNotFoundException` 经通用 handler 可能映射 400。
- 风险：前端无法区分 validation 与资源消失，错误 UX 与 reconcile 错误。
- 候选：A 保持 endpoint-specific；B 统一 stable error envelope。
- 推荐：B：所有 Project command not-found 为 404 `{code:'PROJECT_NOT_FOUND'}`；validation 400；permission 403；stale/running 409；5xx 不泄漏内部异常。
- 待批准合同：统一 error envelope 与 endpoint mapping，不新增 endpoint。
- Permission：沿各 endpoint。Revision：404 不推进。Reconcile：404 对 create/delete operation 按 operation identity另行判定。Backward compatibility：保留 `error/Error` 读取过渡 decoder。
- 测试草案：GET/PUT/DELETE 404 parity、400 validation、403、409、legacy decoder。

### D-PROJECT-05 Explicit open authority

- 当前事实：`Project.RecordOpen()` 存在但当前代码无调用；`GET projects/recent` 读取 `LastOpenedAt`，打开 detail/Workspace 没有明确 command authority。
- 风险：recent 列表陈旧；若 GET 隐式写入会破坏查询语义与 revision。
- 候选：A GET detail 隐式记录；B `POST projects/{id}/open` command；C 纯前端 localStorage。
- 推荐：B；使用现有 Project/Application authority记录访问投影，不能用 localStorage 作为正式 recent authority。该元数据不得静默造成 Flow save conflict。
- 待批准合同：`POST /api/projects/{id}/open` request 可带 clientRequestId；response 返回 Project summary/openedAt；明确是否影响 PersistenceRevision（推荐不影响业务内容 revision）。
- Permission：Authenticated。Reconcile：GET recent。Backward compatibility：现有 GET recent 保持。测试草案：open→recent、并发 save、404、role、重复 open。

### D-PROJECT-06 Template create

- 当前事实：模板 CRUD endpoint 已存在；`CreateProjectRequest` 仅 Name/Description/Flow/GlobalVariables，没有 templateId。
- 风险：前端自行拉模板再拼 Project 会复制迁移、metadata、save 与 partial-success 逻辑。
- 候选：A 前端组装；B 扩展 create request `templateId`；C 第二 template-create endpoint。
- 推荐：B；禁止 A/C。由 `ProjectService`/`ProjectSaveCoordinator` 在同一 create operation 中解析模板并创建。
- 待批准合同：`POST /api/projects` 增加可选 templateId，与 D-PROJECT-01 clientRequestId 合并；response 仍是 canonical ProjectDto。
- Permission：`CanEditProject`。Revision：完整创建后 0。Reconcile：同 create identity。Backward compatibility：templateId optional。
- 测试草案：template found/not-found、migration、idempotency、partial failure、permission、no-template parity。
