## 交付范围

- Security policy：密码最小长度、会话超时、失败锁定次数使用 generic `security` scoped write，仅 Admin 可写。
- 修改本人密码：使用既有 `POST /api/auth/change-password`；Admin/Engineer 可操作，Operator 不会进入 Settings route；提交完成或离开分区后清空旧密码和新密码。
- Admin 用户管理：使用既有 `/api/users`、`/api/users/{id}`、`/api/users/{id}/reset-password` 完成列表、创建、编辑、删除、重置密码；用户记录不进入 AppConfig draft。
- Database：使用既有 `GET /api/settings/database/status` 和 `POST /api/settings/database/backup`；status 中的 database/backup/package path 只做合同校验，丢弃后不进入 UI projection；backup result 只显示时间和大小元数据。
- Database status/backup 继续 Admin-only；Engineer 不发起数据库请求；backup 需要确认，结果未知时不推断成功。

## 敏感字段与失败语义

- decoder 对 password、passwordHash、token、backupPath 等字段做 strict rejection 或显式丢弃；用户 projection 只保留 id、username、displayName、role、isActive、lastLoginAt。
- password、用户初始密码、重置密码只存在于当前请求和短生命周期表单内存；组件 finally/unmount 会清空，未写入 localStorage、Pinia、query cache、owner projection、日志或截图。
- databasePath、backupRootDirectory、packageRootDirectory、backupPath 不进入 Settings 状态、反馈或 Browser 结果断言。
- 401/403/validation/decode/network/unknown outcome 通过已有 Settings error/feedback model 分类；网络或 abort 的 mutation 结果显示“结果未知”，要求重新读取后再决定是否重试。
- 保存结果不把 persisted、effective、restart 混成一个“已应用”；账户操作使用 reload-dependent，数据库维护使用 runtime-operation。

## 权限与 owner 结论

| 操作 | Admin | Engineer | Operator |
|---|---:|---:|---:|
| Security policy generic write | allow | forbidden | route forbidden |
| 修改本人密码 | allow | allow | route forbidden |
| User list/CRUD/reset | allow | forbidden | route forbidden |
| Database status/backup | allow | forbidden | route forbidden |

每个操作都绑定 `SETTINGS_ENDPOINT_MATRIX` 的具体 endpoint contract，再进入同一 section 的串行 coordinator；未知或 excluded endpoint 不会因 route 权限而执行。权限变化时 Database/User 面板清除旧 Admin-only projection，owner dispose 后旧请求结果不能回流。
