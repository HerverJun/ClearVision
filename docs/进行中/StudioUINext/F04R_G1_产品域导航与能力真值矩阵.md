# Studio UI Next F04-R G1 产品域、导航与能力真值矩阵

> 状态：`APPROVED_FOR_G2`
> 性质：G2 已批准的产品信息架构输入；不授权修改页面或路由。

## 1. 冻结原则

产品结构来自真实用户任务、Legacy 成熟语义、当前后端合同和 Next 单一 Owner 架构，不根据已有 Vue 页面反推。当前 Stitch 四栏不是产品权威；Overview 也不能替代真实产品域。

分类只使用：

```text
DEFAULT_VISIBLE
ROLE_RESTRICTED
PROFILE_RESTRICTED
READ_ONLY_ACCEPTED
INTERNAL_ONLY
DEFERRED_TO_F05
BLOCKS_DEFAULT_ENTRY
```

`BLOCKS_DEFAULT_ENTRY` 指阻塞 Next 替代 Legacy 成为正式默认入口，不等同于阻塞受控 F04-R pilot。

## 2. 导航提案

### 2.1 产品任务导航

建议的完整产品地图顺序：

```text
工程 -> 流程（仅当前工程上下文） -> 检测 -> 检测结果 -> 工作站监控 -> AI 工程助手 -> 系统设置
```

受控 F04-R pilot 只显示真实可用项：

```text
工程 -> 流程（打开工程后） -> 检测结果
```

`工作站监控` 仅在生产可达的 read profile 明确开放后显示。`检测`、`AI 工程助手`、`系统设置` 在能力未实现前从主导航卸载，不以长期 disabled 按钮或空页面占位。

### 2.2 工具与身份导航

```text
系统诊断 -> 账户（身份、修改密码、退出） -> 关于
```

这些属于顶栏工具/账户菜单，不与七个主任务域争夺固定主导航空间。内部 Labs 永不进入正式产品导航。

### 2.3 默认落点

推荐登录后落到 `/projects`。`/overview` 可保留为非权威摘要页，但不再承担“产品首页替代所有域”的角色。是否删除主导航中的“概览”以及根 redirect 是否改为 `/projects`，必须由产品负责人在 Prompt 2 批准。

## 4. 强制纠偏处置

| 当前问题 | G1 提案处置 |
|---|---|
| “设置”指向“诊断” | 删除等价假设；未来 `/settings` 与 `/diagnostics` 两个独立语义。未实现前隐藏设置，不改名伪装 |
| 诊断语义被吞并 | 保留 `/diagnostics` 与 Admin/Engineer role guard，放入工具导航 |
| 未实现能力用禁用按钮冒充 | 检测、AI、设置从受控 pilot 主导航真实卸载；产品地图与 F05 roadmap 仍保留 |
| 流程无工程上下文 | 只允许 `/projects/:id/workspace`；无工程时不提供虚假流程 route |
| 高频工程操作都进“更多” | 创建、导入、导出、保存、Formal Run/Stop、全局变量、最终判定按场景保持直接入口；危险/低频项才进菜单 |
| Overview 替代真实域 | 推荐 `/projects` 为落点；Overview 仅摘要，不承载缺失域 |
| 检测/结果/监控边界模糊 | 检测=执行控制；检测结果=历史结果与技术追溯；工作站监控=Station 状态和现场处置 |
| Next 无页面导致旧能力消失 | 所有 Legacy 域均保留在本矩阵与 F05 队列，隐藏只影响当前 profile，不代表删除 |
| Stitch 四栏被当作权威 | 工作区 composition 可重做，但 canonical Canvas 和 owner 树不可复制 |

## 6. 已批准决策（G2 输入）

1. 完整产品地图保留“工程、流程、检测、检测结果、工作站监控、AI 工程助手、系统设置”；Pilot 只挂载工程、上下文流程、检测结果。
2. 未实现的检测、AI、系统设置和未获批工作站操作域在 Pilot 中真实隐藏，不保留长期 disabled 占位。
3. 登录默认落点为 `/projects`；`/overview` 仅可作为非权威摘要/内部页。
4. 结果域统一用户文案“检测结果”；Evidence 属结果详情，不扩展为 F04-R 分析域。
5. 工作站监控只读 profile 保留但不默认显示；`Studio2.StationsRead` 必须进入现有 startup authority 后才能真实可达。
6. 检测、AI、系统设置及完整 Station 操作继续阻塞 Next 正式默认入口和 Legacy 退役，进入 F05 合同波次。
