## 7. DPI authority

代码事实：

- Desktop `.csproj`：`ApplicationHighDpiMode=PerMonitorV2`；
- `Program.Main`：在 WinForms 启动序列中显式调用 `Application.SetHighDpiMode(HighDpiMode.SystemAware)`，且未检查返回值；
- `app.manifest`：没有 DPI awareness 声明；
- WebView2 smoke：通过 `--force-device-scale-factor` 模拟 scale；
- Canvas：通过 JS `window.devicePixelRatio` 设置 backing store。

以上事实不能证明当前进程实际 awareness。Prompt 1 未启动用户桌面，也未执行外部进程 DPI 查询：

```text
EFFECTIVE_RUNTIME_DPI_MODE=NOT RUN
DPI_AUTHORITY=Desktop.csproj ApplicationHighDpiMode=PerMonitorV2
```

唯一 authority 采用 Desktop `.csproj` 的 `PerMonitorV2`。Prompt 2 已移除冲突的 `SetHighDpiMode(SystemAware)`；`app.manifest` 继续不声明第二套 DPI awareness，并由 focused architecture guard 防止三重权威复发。

证据必须分层报告：项目属性、`SetHighDpiMode` 调用、manifest、进程实际 awareness、WebView2 simulated scale、JS `devicePixelRatio`、browser DPR、真实 Windows system scale 和 per-monitor move 互不替代。

## 13. Prompt 2 StartupConfigV1 与最小 Platform

Desktop 只在 StudioUI decision 活动时注入：

```ts
interface StudioStartupConfigV1 {
  readonly schemaVersion: 1;
  readonly uiKind: 'studio-ui';
  readonly hostKind: 'desktop-webview2' | 'browser-test';
  readonly apiBaseUrl: string;
  readonly studioUiBasePath: '/studio/';
  readonly featureFlags: Readonly<Record<string, boolean>>;
}
```

- Desktop V1 顶层精确六字段，startup 与 featureFlags 均冻结；window property 不可写、不可配置。
- Legacy 继续使用旧 startup shape 与 `window.__API_BASE_URL__` / CSS alias；StudioUI V1 不写也不读这些 alias。
- Desktop reader 缺失或非法即 fail-fast；browser-test 必须传显式 fixture；两者都校验 loopback HTTP(S) 与页面同源。
- `src/app/studioPlatform.ts` 是唯一 Platform composition owner：读取已验证 startup、创建 Host/API、向 Vue provide，并在 unmount 时幂等 dispose Host。
- `platform/host/webView2HostAdapter.ts` 是唯一直接 WebView2 访问文件；browser fake 明确标记 `browser-fake`，不冒充 WebView2。
- `platform/api/apiTransport.ts` 是唯一直接 fetch 文件；只支持 GET、AbortSignal、JSON/empty body、动态 token provider 与 network/abort/decode/HTTP 分类错误。
- 相对 API path 固定在 injected `/api/`；根相对只允许公共 `/health`。没有端口发现、重试、登录跳转、EventSource、写方法或业务 SDK。
- bootstrap 失败时只渲染最小 diagnostic，不使用猜测配置继续 mount。
