以下裁决是 F07 的产品边界。G1 只能把它们翻译成 contract、permission matrix、owner lifecycle 和证据门禁，不得由 capability 实现者重新解释。

| D02 | Next UI preferences 与 AppConfig 产品主题独立 | UI preference 是 UI projection；不把 Next theme/density/reduced-motion preference 写入 AppConfig General theme，也不反向覆盖 |
| D03 | F07 不新增 conditional revision | 沿用单 Settings owner、section 串行写和现有后端无条件 revision / last-write-wins；UI revision 只做草稿与 stale 防护 |
| D04 | generic `/api/settings` 只负责 General、Storage、Runtime、Security | PLC、TCP、Camera、Station、AI 只走专用 endpoint；不得 generic fallback、双写或把潜在后端 overlap 当成新前端合同 |

## 4. Authority 与 section 范围

G0 冻结的是既有后端 authority 的消费边界。前端不能把投影、草稿、localStorage、Pinia、DOM 或缓存提升为产品配置权威。

| section / 能力 | 权威 | F07 承诺的入口或范围 | 明确边界 |
| --- | --- | --- | --- |
| Settings route | 现有认证、session 和 API permission policy | 建议由唯一 Next Settings owner 承载；仅 Admin / Engineer 可达 | route guard 不能替代或扩大服务端授权；Operator forbidden |
| General / Storage / Runtime / Security | `IConfigurationService` / `AppConfig` | generic `PUT /api/settings` 的明确 scoped write；只限四类 | 不提交完整 AppConfig；不新增 conditional revision；不改默认值 |
| Next UI preferences | `UiPreferencesOwner` 的 UI projection | 继续使用现有 UI preference owner 语义 | 与 AppConfig 产品主题分离，不进入产品 Settings save chain |
| PLC | 既有 PLC service / `IConfigurationService` | `/api/plc/settings`、`/api/plc/mappings`、`/api/plc/test-connection` | 不通过 generic `/api/settings` 写 PLC；test 不等于持久化或长期 session |
| TCP | `ITcpDeviceManager` 与现有 TCP profile authority | `/api/tcp/profiles/**` 专用 profile/runtime endpoints | 不保存 socket、server、frame log 或虚假 connected 状态到前端 |
| Camera system administration | `CameraManager`、frame/trigger coordinators | `/api/cameras/**`、`/api/trigger-input/**`；系统 discovery、binding、trigger、diagnostics、preview | Settings 管理系统能力；active stream mutation 遇 `409` 必须 fail closed |
| Workspace camera binding / preview | 既有 `CameraBindingEditorOwner` 与 Workspace owner | 工程绑定和预览继续留在 Workspace | Settings 不接管工程绑定，不复制长期 preview/session owner |
| Station communication | `StationCommunicationSettingsStore`、`StationIngressOptions` 与既有 endpoint | `/api/station-communication/settings`、`/token`；展示 restart result | 不写 Station 本地文件；当前 token 语义可消费，后端安全升级为 `F07-D01` |
| AI model management | `AiConfigStore` 与 DPAPI secret store | `/api/ai/models/**`、`/api/ai/reasoning-support`；model CRUD、角色/default、reasoning、test、key keep/replace/clear | 不读取 `ai_model_secrets`；不由 AgentRun/F06 owner 写 model config |
| RuntimePreview Pilot | 既有 metadata-only developer surface | 保持 developer-only，不纳入普通 F07 Settings | 不扩展为正式执行、结果或普通用户模型管理 authority |
| Database | `VisionDatabaseMaintenanceService` | 首轮只读 status 与 backup | restore、cleanup、repair、全局 reset 延期；前端不实现 recovery chain |
| Settings Import/Export | 当前没有 Settings bundle endpoint 或版本化合同 | F07 排除 | 不把 `GET /api/settings` dump、AI key、Station token、密码或 backup path 组成 bundle |
| Project / Flow / GlobalVariables / Runtime Package / Station site | 各自现有 Application、Runtime、Station authority | 不由 Settings owner 代理 | 继续使用 `ProjectSaveCoordinator`、Runtime、Station 现有链路 |

generic `/api/settings` 即使在后端当前仍识别 `communication` 或 `tcpCommunication` 等潜在重叠字段，F07 也不把它们当作 Next 写入口。PLC、TCP、Camera、Station、AI 的写操作必须走专用 endpoint；不通过前端新增第二 authority 来修复后端 overlap。

## 5. 权限冻结

下表是 UI route、section visibility 和现有 API policy 的投影，不是新的后端权限合同。所有 401、403、409 和 validation failure 都必须保持可解释，不能由前端自动重试或伪造成功。

| 能力 | 既有权限事实 | G0 冻结的 UI 行为 |
| --- | --- | --- |
| `/settings` route | 本轮产品裁决为 Admin / Engineer；Operator 禁止 | Admin / Engineer 才能进入；Operator 直接 forbidden，不展示只读概览 |
| Generic settings read | Admin full；非 Admin 由现有 endpoint 返回 safe subset | Engineer 只能看到服务端实际返回的 safe projection；不因新 UI 获得更多字段 |
| Generic settings write / product theme | Admin | 只显示 Admin mutation；不改变后端 policy |
| PLC read / test | Engineer / Admin | Engineer 可按既有 endpoint 读取和测试；保存 mutation 仍由服务端 Admin policy 决定 |
| PLC settings / mappings write | Admin | 前端不通过隐藏字段或 generic PUT 绕过 Admin policy |
| TCP read / runtime operation | Engineer / Admin | 连接、发送、server、frame 等操作继续由现有 policy 决定；profile write 仍 Admin |
| Camera discovery / read / preview / trigger | Engineer / Admin | 仅投影既有 hardware policy；不把前端可见性当成设备授权 |
| Camera binding write | Engineer / Admin | Settings 与 Workspace 都服从后端 `409` 和 owner 协调，不能互相抢写 |
| Station communication / token | Admin | Engineer 可进入 route 但不能获得 Station Admin mutation；token 操作保持 Admin policy |
| AI model CRUD / activate / default / test | Admin | Engineer 不因进入 Settings route 而获得 model mutation |
| Database status / backup | Admin | 只开放既有 Admin maintenance policy；延期操作不显示入口 |
| User management | Admin；change-password 使用既有 authenticated session operation | 不把用户记录或密码放入 Settings draft |

G0 不新增角色、claim、后端 guard 或 permission endpoint。Operator 被禁止是产品 route 决策，不是要求把现有后端 safe subset 改造成新的权限模型。

## 8. 回滚边界

G0 本身没有产品代码或运行时状态可回滚。后续 F07 的第一回滚选择冻结在以下边界：

1. 关闭 Next Settings capability 或保持 `/settings` 不可达，回到 Legacy Settings；不删除 Legacy 文件，不改变默认入口。
2. 单个 section 失败时停止该 section owner、禁止继续写入并保留既有 backend authority；不通过 generic endpoint 扩大写面。
3. Camera active stream 冲突时保留既有 binding/stream，显示后端 `409` 并要求现有 owner 先停止；不强行覆盖，不用第二 preview owner 抢占。
4. Database 问题由既有 backend/database recovery 处理；F07 不执行 restore、cleanup、repair 或全局 reset，也不删除用户数据。
5. Station token 问题停止 Station Settings section，继续使用 Legacy/既有 endpoint；不复制 token 文件、不回滚 token secret、不在前端伪造安全升级。
6. AI secret、Project、Flow、Runtime Package、Station site、正式结果和执行状态都回到各自 authority；不使用 localStorage、Pinia 或 Settings bundle 做恢复。

不得以“回滚”名义修改稳定线、处理其他 worktree、覆盖用户文件、reset 工作树、切换分支或把未批准的后端修复混入 F07。
