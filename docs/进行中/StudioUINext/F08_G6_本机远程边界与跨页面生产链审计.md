
G6 在既有 Workspace、Formal Run、Continuous Inspection、Runtime Package、Station fleet/detail 与 Results capability 上建立白名单化生产追溯导航，并在 Station 详情组合现有 package、command、audit、active identity 与 result 权威。实现没有新增后端 endpoint、持久化模型、跨 capability store、EventBus、HTTP client、保存链、Canvas、HostBridge 或图片上传通道；每个目标页面仍由既有唯一 owner 在 mount 后重新读取 authority。

## 2. 实现事实

### 2.1 白名单 deep link 与 authority reread

- Workspace、Formal Run 与 Continuous Inspection 的结果入口携带精确 `projectId/resultId`；Runtime Package 成功态携带 `packageId/projectId/revision` 进入 Station fleet。
- Station fleet 按 package、project 与 revision 投影生产身份，进入 Station detail 时保留合法筛选；Station result 入口携带精确 `stationId/resultId`，Results 查询把 `stationId` 发送给既有 endpoint，并拒绝返回其他 Station 的行。
- route 只保存稳定、非敏感 identity 与筛选。Results、Station fleet/detail 的 `returnTo` 仅接受明确内部路由及逐键白名单；外部 URL、协议相对 URL、反斜杠、fragment、嵌套 `returnTo`、未知或敏感 query key 均被拒绝。
- 导航使用真实 `RouterLink`，保留 Ctrl/中键新开语义；目标页面不读取来源页面的易失 Pinia 对象、route payload 或 localStorage authority。

### 2.2 生产追溯链与身份比较

- Station 详情的生产追溯链按来源工程/正式修订、运行包、部署命令与审计、工作站当前身份/运行、最近结果顺序组合当前页面已经读取的权威。
- 部署命令必须是 payload 中 packageId 与当前激活包一致的 `DeployPackage`；无关命令不回退关联，失败或未终态命令不能产生“身份闭合”。
- active package、Station 当前身份与最近结果比较 package、来源工程/修订、package/execution flow hash、decision hash、execution snapshot 与 run/result identity。旧数据、归档窗口、离线、无权限或缺字段均明确降级为“身份不完整”，不猜测关联。
- hash 显示首尾可比较摘要，同时提供完整值复制入口；不以视觉截断后的相同片段判定身份相等。

### 2.3 本机/远程产品边界与角色门禁

- 本机结果继续通过既有 authenticated image/evidence 链读取；Station 追溯面明确投影 `not-uploaded`，不会创建远程图片 owner 或请求 `/api/images/*`。
- 当前角色不可进入工程时只显示受限说明；Admin command/audit/package 详情不可读时保持只读监控摘要和明确缺口，不通过 deep link 扩权。
- session 过期、403、offline、旧 identity 或 authority 读取失败沿用目标 capability 的既有加载/错误/只读状态；route 本身不携带 token、路径、secret、完整 payload 或 evidence 引用。

## 3. 独立审计修复

独立审计发现并关闭四类缺口：

1. 初版曾从当前激活包回退关联不相干的部署命令；现仅接受 command payload packageId 精确匹配，避免拼出虚假生产链。
2. 失败或未终态部署、缺少 legacy identity 时曾可能得到过强的闭合结论；现这些状态统一降级为 partial，并说明具体缺口。
3. 初版比较未覆盖 result package flow、execution flow、revision、decision hash 与 snapshot；现均与 Station 当前身份逐字段比较并显示不一致原因。
4. return route 校验中的控制字符实现触发 lint，且 1366x600 截图在固定顶栏下 framing 不完整；现使用显式 code-point 检查，并修正短屏截图定位及新追溯面的混合英文标签。

修复后重新执行 StudioUI lint、typecheck、全量 unit、production build、Station endpoint、Results/Stations 与 Workspace/Continuous Browser 场景、三档视觉场景和静态反模式检测，未发现 G6 P0/P1 缺口。

## 6. 停止条件审计

- deep link 不依赖易失 Pinia 对象、route payload 或 localStorage 才能恢复，目标页 mount 后重新读取 authority。
- URL 与 UI 日志不携带 token、文件路径、secret、完整 command/result/package payload 或敏感 evidence 引用；return route 使用逐路由、逐 query key 白名单。
- 未创建第二份 package、command 或 result 持久化模型，也未新增共享 store/EventBus/HTTP client。
- Station 图片保持 `not-uploaded` 产品边界；没有默认上传要求、合同或实现。

因此 G6 停止条件均未触发，独立审计结论为 `PASS`。
