## 交付范围

- General：软件标题与产品主题使用 AppConfig generic scoped write；历史 `autoStart` 只读禁用，不转化为新能力。
- Storage：保存路径、保存策略、保留天数、最低可用空间支持草稿、校验、保存、放弃修改；磁盘占用只走 `/api/settings/disk-usage` 诊断读取。
- Runtime protection：自动运行、连续 NG 停止、缺料超时、保护规则使用 Runtime scoped write；`RuntimePreview Pilot` 仍不进入普通 Settings。
- 保存请求只由 `saveGenericSection(section, value)` 构造 `{ saveScope, [section] }`，不提交整份 AppConfig，也不回写 PLC、TCP、Camera、Station 或 AI authority。
- 保存成功后只以服务端返回的 `config` 替换 owner authoritative projection；“已保存”“投影已更新”“重载要求未知”在反馈模型中分开表达。
- Engineer 只消费服务端实际 safe projection；Admin 才显示 generic mutation；Operator 在 Settings route 直接 forbidden。

## 合同与 owner

- 复用 `ProductRuntime.api` 和既有 `/api/settings`、`/api/settings/disk-usage`。
- endpoint matrix 对 generic section 固定为 General、Storage、Runtime、Security；未知、excluded、route-only endpoint fail closed。
- 所有 section 写进入唯一 `SettingsOwner` 的 `SettingsWriteCoordinator`，同一 section 串行，refresh、权限变化、route leave、dispose 会使旧写 stale/cancelled/disposed。
- Next UI preferences 没有进入 AppConfig General.theme；未修改默认入口、默认值、Legacy、CI 或共享 HTTP 基础设施。

## 不伪造的能力

- 没有新增宿主路径选择器；Storage 路径只能手工输入并由服务端校验。
- 没有新增立即清理 endpoint；磁盘占用不是保存成功，也不是清理完成。
- `autoStart` 保持历史禁用字段；没有修改配置 normalize 或默认值。
- `runtimePreviewPilot` 只在 decoder 中作为后端投影中的保留字段校验，不提供普通用户 Settings 表单。

- 未运行真实 WebView2、Windows 125% DPI、Release publish、CI 和真实硬件；均不得写成 PASS。
- 工作树中另有未跟踪的 `ClearVision.Product/src/capabilities/settings/SettingsDatabasePanel.vue`，不在当前 StudioUI 入口内，本轮保留且未纳入提交，避免覆盖未知用户改动。

## 结论

G3 的 General、Storage、Runtime protection 已在既有 Settings Shell、唯一 owner 和 scoped generic contract 上完成。G4 可复用同一 owner 与 coordinator；不需要新增 authority、HTTP client 或持久化链。G5 仅建议在本报告和 G4 报告评审通过后进入下一轮，不在本轮开始实现。
