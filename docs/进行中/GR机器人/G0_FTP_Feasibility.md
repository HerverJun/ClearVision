# G0 FTP 可行性独立审计

> 结论：`EXPERIMENTAL`。已有本地下载快照证明工程文件和静态文本存在，但没有证明外部工程可被控制器识别、加载、编译、运行或重启持久化；且与官方手册形成直接冲突。FTP 不进入正式产品主链路。

## 1. 审计范围与禁止动作

本轮仅以本地文件进行只读审计：未登录 FTP、未上传、未覆盖、未删除、未备份远端文件，也没有尝试让控制器加载任何文件。任何 `tmp/` 中的 FTP 脚本均未运行，且不应提交。

## 2. 原始手册结论

来源：`C:\Users\11234\Desktop\GR机器人示教器手册 v3.0-1.pdf`（SHA-256 `5F56D18C9BD48A112EA3629C5CD7C8C4ED4241EB4317C70850BF68415415FD74`），PDF 页 90：

> “不支持导入由外部编辑的程序的操作。”

这是一条 `MANUAL_CONFIRMED` 限制。它不等于“FTP 一定不能登录或下载”，但明确否定了“外部编辑文件已经是官方可部署程序”的假设。

## 5. 若未来获得独立授权的验证链

不属于本轮，也不属于 G0 的默认主链路。只有安全负责人、设备所有者和厂商支持路径都明确授权后，才能在非生产控制器按以下顺序进行，每一步都先备份并记录 hash：

1. 只读确认认证方式、目录结构、下载一致性；不把匿名性假定为可用。
2. 验证受控上传到隔离测试目录，不覆盖活跃工程；记录 FTP 命令/响应与文件 SHA-256。
3. 在示教器中检查该工程是否出现在列表、是否可加载、是否可编译，且不执行运动。
4. 用只读/无运动程序验证运行；再验证重启后仍存在和版本一致。
5. 任一步失败、出现手册限制、目录权限不清或控制器状态异常即停止并恢复备份；不得把 FTP 当运行时控制通道。

在完整链路和厂商支持没有同时证明之前，G7 必须保持关闭，FTP 只能标记为 `EXPERIMENTAL`，不成为 ClearVision 生产必须能力。
