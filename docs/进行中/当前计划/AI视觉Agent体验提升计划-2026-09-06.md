# AI 视觉 Agent 体验提升计划

状态：待实施。

## 1. 目标与方向

将 Agent 提升为**以流程和验证结果为中心的视觉工程工作台**。当前质感不足主要来自：状态与操作重复、空间分配失衡、流程缺少主视觉地位，以及“检查通过”和“实际效果已验证”的表达混淆。

本轮按已确认的方向实施：**通用流程生成、体验重构与现有能力接入、Agent 内节点预览、对话按阶段展开**。沿用当前已保存的优化与修复成果。

## 2. 工作台与视觉

- **确定内容主次**：任务栏回答“当前进展和下一步”；主区展示流程或实际结果；上下文区处理待办；对话承接需求补充与解释。
- **收敛导航**：保留“方案 / 构建与验证”一级标签。构建区使用一条紧凑导航切换“流程 / 节点预览 / 变更”，每次展示当前视图，避免持续增长的报告页面。
- **自适应布局**：桌面对话栏保持 320px。工作台自身可用宽度达到 960px 时，采用流程主区加 320px 上下文区；不足时上下排列，当前必需事项或失败原因在前。沿用 1180px 对话抽屉分界，低于 600px 对话全宽。
- **一个主要操作**：规划时取消规划，待补齐时定位待办，就绪时开始构建，失败时查看问题，可应用时打开应用预览，应用后手动预览所选节点。构建中沿用现有可用操作。AI 页面中的全局“运行”降低视觉权重。
- **待办与节点联动**：延续权威缺项派生的统一列表，按构建前、运行前必需分组。选择待办定位对应节点，选择节点显示相关待办；默认展开首个必需事项，确认成功后推进，失败保留输入、错误与焦点。
- **流程成为视觉主体**：规划阶段展示明确标注的推荐步骤；构建后展示真实节点、端口、分支和连接。图数据不足时显示可读列表。任务理解压缩为两行，技术证据与已通过检查进入详情。
- **统一视觉规格**：中性灰与品牌红，红色集中于主操作和焦点；正文 14px、辅助 12px、区块标题 16px、任务标题 18px；字距为 0，间距使用 4/8/12/16/24px，控件圆角 6px、弹窗 8px。区域采用平面布局和分隔线，使用本地 Lucide 与现有算子图标。
- **对话与输入**：无手动偏好时，输入和规划阶段展开，构建阶段收起；已有本地偏好优先，窄屏开关独立。正在输入时不自动收起。保留真实未读、历史恢复、自增高输入、附件状态和中文输入行为；空白页保留四个业务示例及最多三条最近任务。

## 3. Agent 内验证闭环

- **应用前**：生成流程使用独立只读画布，支持平移、缩放、适应视图和节点选择。待办仍通过现有表单处理，预览草稿不修改工程画布。
- **应用后**：工程与执行上下文就绪后启用手动节点预览，执行所选节点及其上游子图。请求发起后进入“节点预览”，展示实际图像、关键输出、耗时及诊断；纯数值、文本结果使用对应结果布局。
- **准确表达验证程度**：分别显示“结构检查”“元数据预演”“真实样本验证”。没有样本报告时显示“未验证”；一次节点预览成功只代表对应节点及本次输入，不能升级为整条流程验证通过。
- **明确输入来源**：默认使用流程已绑定的采集输入；已有有效采集帧可显式选用。显示实际文件或采集来源，缺失时定位对应资源配置。对话附件的发送状态与运行样本独立，预览输出不自动成为下一次输入。
- **处理工程保存过程**：区分“已应用到画布”“工程准备中”“预览可用”。等待现有工程创建和保存完成，确认工程 ID、版本及执行上下文有效后启用预览；失败保留已应用流程，提供原因和重试入口。
- **结果随上下文失效**：结果绑定工程、节点、流程版本、参数和输入身份。同一工程修改后刷新只读图，旧结果标记过期，允许手动重新预览；切换工程、撤销应用或恢复不匹配历史时解除预览关联。
- **保持应用可审查**：复用现有应用差异预览，优先展示删除、重连及参数前后值；保留取消、预览失效、确认与撤销路径。历史恢复默认进入当前待办，仅有消息的会话直接打开对话。

## 4. 接口与实施顺序

- **最小接口扩展**：`FlowCanvas` 增加可选只读交互模式，现有编辑器默认行为保持兼容；只读实例不注册修改流程的全局快捷键。`AiPanel` 增加可选预览适配器，提供上下文查询、状态订阅、节点选择、请求、取消及结果读取。
- **复用执行与展示**：由应用层连接现有 `NodePreviewCoordinator` 和结果展示模型，统一管理活动预览视图。隐藏的编辑器预览面板暂停自动预览；切换视图时释放请求与订阅，避免多个面板争抢节点或显示串线结果。
- **第一批：布局与编排**。完成任务栏、内容视图、对话偏好、待办联动及准确状态文案，验证首屏效率和深浅主题。
- **第二批：流程与结果**。接入独立只读画布、工程准备状态、手动节点预览和结果失效处理，验证完整连续操作。
- **第三批：恢复与验收**。完成历史、应用差异、取消与撤销回归，合并 Agent 局部重复样式，完成截图及 WebView2 验证。
- **兼容边界**：继续使用原生 JavaScript、CSS、WebView2；HTTP、WebView 消息、后端结构和会话快照保持兼容。新增状态限于本地偏好及临时界面状态。本轮不增加模型推理、自动调参、ROI 编辑或新的执行端点。

## 5. 验收标准

- **首屏效率**：1366×768、1024×768 下，无滚动即可看到首个必需问题与有效控件；失败原因及修复入口同屏可见，当前主要操作不重复展示。
- **视觉质量**：检查 1920×1080、1366×768、1024×768、390px 的深浅主题；无横向溢出、遮挡、嵌套大框或重复焦点框，正文对比度至少 4.5:1。过渡为 120–160ms，并支持减少动态效果。
- **连续流程**：覆盖需求输入、澄清、构建、资源绑定、应用取消与确认、等待工程就绪、节点预览、修改后过期、重试、撤销和历史恢复；同时验证严格与草稿模式。
- **异常与隔离**：覆盖真实 GUID 与 `agentTempId`、分支和多资源、长中文与路径、保存失败、无样本、非图像输出、超时取消、过期响应、只读历史。只读画布不得改变正式流程、撤销栈或抢走输入焦点。
- **验证方式**：运行现有前端单测、Agent 合同测试、Shell、Clarification、Build、Responsive Playwright 及预览回归；必要的 .NET 测试按项目串行。使用内置浏览器审查截图，视觉基线须逐张确认；发布前完成 WebView2 100%/125%/150% DPI 检查，并单独记录无法完成的验证项。
