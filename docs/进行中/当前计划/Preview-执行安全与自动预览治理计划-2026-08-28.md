# Preview 执行安全与自动预览治理计划

## 来源与目标

本计划承接 [预览手动执行算子审计（2026-07-09）](../../归档/已关闭事项/2026-08-28-待复核审计治理归档/PreviewManualOnlyOperatorsAudit-2026-07-09.md) 的产品决策、技术验证和测试补强事项，是该主题的唯一 active 入口。

目标是统一 NodePreview、OperatorPreview、autotune preview 和前端自动预览的安全边界，消除基于文本子串的误伤，同时确保相机、外部 I/O、持久化和状态型算子不会因“手动预览”绕过执行准入。

## P0：autotune preview 准入

- [ ] 确认 `/api/autotune/flow-node/preview` 的当前可达调用方、鉴权和产品保留必要性。
- [ ] 若入口保留，在执行 debug flow 前复用统一的 `ExecutionAdmissionService` 准入；若入口已废弃，删除路由和调用方并补不可达守卫。
- [ ] 覆盖目标节点及其上游依赖；存在 `ImageSave`、`TextSave`、`HttpRequest`、数据库、MQTT、TCP、串口、PLC、真实相机或标定副作用时必须拒绝真实执行或进入明确 dry-run。
- [ ] 增加 autotune preview 的 endpoint/service 参数化测试，验证拒绝原因码和无副作用事实。

## P1：自动预览成本策略

- [ ] 将 `HIGH_COST_TEXT_HINTS` 的模糊子串判定收敛为显式 operator type、catalog metadata 或可审计策略表。
- [ ] 第一批复核并恢复 text-only 误伤：`LineMeasurement`、`GeometricTolerance`、`CaliperTool`、`BlobLabeling`、`HistogramAnalysis`、`ParallelLineFind`、`QuadrilateralFind`、`FrequencyFilter`、`PhaseClosure`、`GlcmTexture`。
- [ ] 第一批复核轻量后处理：`BoxFilter`、`BoxNms`、`DetectionSequenceJudge`、`DualModalVoting`、`EdgePairDefect`。
- [ ] 对 AKAZE/ORB、模板/形状匹配、ONNX/异常检测/语义分割、3D/点云类保留显式高成本策略，并定义 debounce、取消、超时、缓存和输入规模上限。
- [ ] 生成 catalog 策略快照；新增算子或 metadata 变化导致自动/手动分类改变时必须进入评审。

## P1：相机、无图像输出与 dry-run 产品决策

- [ ] `ImageAcquisition SourceType=file` 保持自动预览；`SourceType=camera` 默认保持手动和后端准入阻断。
- [ ] 若需要受控自动采帧，必须先定义显式开关、权限、冷却时间、设备占用、取消、最近帧/模拟帧来源和失败可观测性。
- [ ] 无图像输出算子继续允许执行时，在工作台展示结构化摘要；不得把 `no-image-output` 呈现成“没有执行”。
- [ ] 为保存、写库、HTTP、MQTT、PLC/TCP/串口、标定、变量写入/递增/计数/触发和脚本类定义只读 dry-run 合同；dry-run 不得访问外部资源或修改运行态。
- [ ] `ResultOutput SaveToFile=false` 可按纯计算预览；`SaveToFile=true` 必须阻断真实写入或进入 dry-run。

## 测试补强矩阵

- [ ] 自动预览 checkbox 关闭后不再请求、重新开启后恢复请求。
- [ ] `getOperatorPreviewCostPolicy()` 参数化覆盖全部 direct high-cost 类型和 text-only false positive。
- [ ] 基于真实 operator catalog 的策略快照测试。
- [ ] `ImageAcquisition SourceType=file` 明确允许自动预览。
- [ ] `ImageAcquisition SourceType=camera` 前端 manual-required 与后端 admission blocked 的端到端一致性。
- [ ] `/api/autotune/flow-node/preview` 的副作用准入测试。
- [ ] PreviewNode/OperatorPreview 参数化覆盖全量 AlwaysBlockedSideEffectTypes、`ResultOutput SaveToFile=true/false` 和 camera/file 分支。
- [ ] 无图像输出算子的结构化预览 E2E 与布局验收。

## 验收标准

- 所有 preview 入口共享可审计的准入结论，同一 flow 在不同入口不会出现副作用边界分叉。
- 模糊文本规则不再误伤第一批轻量算子；策略变化由 catalog 快照测试守门。
- camera、外部 I/O、持久化、标定和状态写入没有真实副作用预览路径。
- 上述 8 类测试全部落地并进入对应默认或正式 Gate，测试人口和 skip 变化可审计。
- 完成产品决策、实现、定向回归和当前 HEAD 证据后，新增闭环报告并将本计划归档。
