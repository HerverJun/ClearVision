# 项目潜在问题并行审计

本次审计按只读方式执行：启动 6 个 gpt-5.5/xhigh 子代理并行检查前端 UI、AgentRun 前后端通讯、后端逻辑、文案注释、性能隐患和测试覆盖；主代理同步复核关键证据。未修改源码、未回滚其它代理变更、未启动测试进程。以下条目均待人工复核和排期修复。

## 前端 UI 与可访问性

1. **参数禁用提示英文直出**
   - 证据：`ClearVision.Product/src/ClearVision.Product.Desktop/wwwroot/src/shared/parameterDependencyRules.js:10` 写有 `File path is disabled...`；`.../features/flow-editor/propertyPanel.js:492` 将规则提示渲染为 `parameter-rule-hint`。
   - 风险：中文界面中直接出现英文规则说明，现场操作员理解成本高。
   - 建议：为规则原因接入中文资源表，避免直接渲染内部字段名。

2. **参数必填校验消息英文**
   - 证据：`parameterDependencyRules.js:137` 写有 `DeepLearning requires...`；`parameterDependencyRules.js:561` 存在默认英文错误。
   - 风险：表单错误或 Toast 可能混入英文和内部参数名。
   - 建议：为 `atLeastOneMessage` 和默认错误提供中文业务文案。

3. **文件选择按钮只有省略号**
   - 证据：`propertyPanel.js:575-576` 的文件输入旁按钮文本为 `...`。
   - 风险：按钮语义弱，屏幕阅读器无法知道用途。
   - 建议：改为“选择文件”，或图标按钮加 `aria-label="选择文件"`。

4. **枚举缺省显示开发态字符串**
   - 证据：`propertyPanel.js:548` fallback 为 `'undefined'`，`propertyPanel.js:552` 写入 `<option>`。
   - 风险：元数据缺失时用户会看到开发态字符串。
   - 建议：展示“未命名选项”，并记录元数据质量告警。

5. **结果状态英文枚举直接展示**
   - 证据：`wwwroot/src/app.js:599` 返回 `Error`；`resultPanel.js:1447` fallback `Unknown`；`resultPanel.js:1455` 渲染状态徽标。
   - 风险：追溯卡片和详情页会出现 `Error/Unknown`。
   - 建议：展示层统一映射为“合格/不良/异常/未知”。

6. **缺陷 fallback 文案英文**
   - 证据：`app.js:580` 使用 `Target ${index + 1}`；`app.js:581` 使用 `Result did not include...`。
   - 风险：实时结果缺陷详情缺失时，用户看到英文占位。
   - 建议：改为中文占位，并优先显示诊断码和来源说明。

7. **结果详情隐藏缺陷提示英文**
   - 证据：`resultPanel.js:2059` 使用 `More` / `Hidden ... more defects`。
   - 风险：长缺陷列表折叠提示不符合中文界面。
   - 建议：改为“还有 N 条缺陷未显示”，并提供展开或查看全部。

8. **工站监控页混入英文和内部字段**
   - 证据：`stationMonitorView.js:1070` 显示 `OK / NG / ERR`；`stationMonitorView.js:1195` 显示 `Ping`；`stationMonitorView.js:1411` 显示 `executionTimeMs`。
   - 风险：生产监控页暴露工程字段名，降低可读性。
   - 建议：展示为“合格/不良/异常”“连通性检测”“执行耗时”。

9. **Runtime Preview Pilot 设置页英文开发文案**
   - 证据：`features/settings/tabs/aiTab.js:33` 通过本地开关启用开发 UI；`aiTab.js:1127` 使用 `Camera allowlist`；`aiTab.js:1134` 使用 `Refresh catalog`。
   - 风险：开关打开后设置页出现大段英文试点功能。
   - 建议：开发 UI 明确隔离，或统一中文化并加“实验功能”标识。

10. **AI 设置表单英文残留**
    - 证据：`aiTab.js:756` 使用 `Planner`；`aiTab.js:848` 使用 `API Endpoint`；`aiTab.js:862` 使用 `Clear saved key`。
    - 风险：模型配置页中英文混排，术语不统一。
    - 建议：统一为“规划模型 / 接口地址 / 清除已保存密钥”等中文术语。

11. **附件删除按钮辅助名称英文**
    - 证据：`features/ai/aiPanelAttachments.js:137` 写有 `aria-label="remove attachment"`。
    - 风险：屏幕阅读器读出英文操作。
    - 建议：改为 `aria-label="移除附件"`，必要时包含附件名。

12. **登录页禁止用户缩放**
    - 证据：`wwwroot/login.html:5` 设置 `maximum-scale=1.0, user-scalable=no`。
    - 风险：低视力用户无法放大登录界面。
    - 建议：移除缩放限制，依靠响应式布局适配。

13. **密码显示按钮被移出 Tab 顺序**
    - 证据：`login.html:45` 为密码显示按钮，`login.html:49` 设置 `tabindex="-1"`；同类设置还在 `login.html:101`。
    - 风险：键盘用户无法聚焦“显示密码”。
    - 建议：移除 `tabindex="-1"`，并同步 `aria-pressed` 状态。

14. **主导航 active 只靠 CSS**
    - 证据：`wwwroot/index.html:77` 初始按钮仅 class `active`；`core/app/viewManager.js:88-90` 只切换 class。
    - 风险：辅助技术无法知道当前视图。
    - 建议：切换时同步 `aria-current="page"`，或采用 tablist/tabpanel 模式。

15. **自定义 Tooltip 只监听鼠标**
    - 证据：`index.html:135` 主题按钮仅有 `data-tooltip`；`shared/components/tooltip.js:36-42` 只委托 `mouseover`。
    - 风险：键盘和读屏用户拿不到工具提示；图标按钮也缺少稳定辅助名称。
    - 建议：图标按钮补 `aria-label`，Tooltip 支持 `focus/blur` 与 `aria-describedby`。

16. **Toast 不会被读屏主动播报**
    - 证据：`shared/components/uiComponents.js:233` 创建容器仅设置 class；`uiComponents.js:292` Toast 仅创建 div；`uiComponents.js:312` 关闭按钮仅 `×`。
    - 风险：成功/错误通知对非视觉用户不可感知。
    - 建议：容器加 `aria-live`，错误用 `role="alert"`，关闭按钮加 `aria-label="关闭通知"`。

17. **新建工程默认占位名为英文**
    - 证据：`wwwroot/src/app.js:1227` 使用 `placeholder: Project_${Date.now()}`。
    - 风险：创建工程弹窗中出现英文默认命名。
    - 建议：改为 `工程_${yyyyMMdd_HHmmss}` 或“未命名工程”。

18. **图像查看器错误提示英文**
    - 证据：`features/image-viewer/imageViewer.js:335` 调用 `showToast('Image load failed: ' + error.message...)`。
    - 风险：加载失败时用户直接看到英文错误。
    - 建议：改为“图像加载失败：...”，并对底层异常做本地化映射。

## 前后端通讯与 AgentRun 契约

19. **附件在 AgentRun 生成链路被丢弃**
    - 证据：`aiPanelGenerateRequest.js:93` 读取附件路径；`aiPanelAgentRun.js:472` 传 `attachments: []`；`AgentRunEndpoints.cs:885` 后端固定 `Array.Empty<string>()`。
    - 风险：带图/文件需求在 AgentRun 路径与旧 GenerateFlow 路径结果不一致。
    - 建议：复用既有附件授权链路，或明确禁用附件入口并提示 metadata-only 限制。

20. **RuntimePreview 授权开关被 AgentRun 强制抹掉**
    - 证据：`aiPanelGenerateRequest.js:479` 传入授权意图；`aiPanelAgentRun.js:476` 固定 `runtimePreviewConsent: false`；`AgentRunEndpoints.cs:895` 后端也固定 `RuntimePreviewConsent = false`。
    - 风险：用户授权状态与工具策略不一致。
    - 建议：保留一次性 consent，后端消费后清除并写入事件诊断。

21. **旧 activeAgentRunId 会过滤下一轮 PlanRun 事件**
    - 证据：`aiPanelAgentRun.js:568` 先按 `activeAgentRunId` 过滤；`aiPanelAgentRun.js:849` 终止只清 `activeAssistantTurn`；`aiPanelAgentWorkspace.js:321` 处理 PlanRun。
    - 风险：完成一次构建后再规划，事件可能被丢弃并卡住。
    - 建议：终止时清理 `activeAgentRunId`，或先判断 PlanRun 再做 build runId 过滤。

22. **旧 activePlanRunId 会导致构建中取消请求打到已完成 PlanRun**
    - 证据：`aiPanelAgentWorkspace.js:674` 记录 plan run；`aiPanelAgentWorkspace.js:1454` 完成后未清 id；`aiPanelGenerateRequest.js:561` 取消逻辑优先取消 plan。
    - 风险：用户以为取消构建，实际构建继续运行。
    - 建议：PlanRun 完成/失败后清 id，进入 Build 前也清理 plan 活动状态。

23. **下层服务可用普通 Append 发布 terminal 事件**
    - 证据：`AgentRunEventStreamService.cs:98` 普通 `Append` 仅在已 terminal 后拒绝；`AgentRunEventStreamService.cs:386` 只有 terminal append 才置 `IsTerminal`；`VisionAgentGenerateFlowService.cs:218` 可发布 `run.failed`；`AgentRunEndpoints.cs:421` endpoint 之后再 `Fail`。
    - 风险：前端先看到 `run.failed` 并关闭流，可能错过更完整失败 payload。
    - 建议：禁止普通 `Append` 发送 terminal 类型，统一通过 `Fail/Complete/Cancel`。

24. **事件流失败不会向上层 reject**
    - 证据：`aiPanelAgentRun.js:269` 回放循环持续运行；`aiPanelAgentRun.js:298` catch 只增加计数；`aiPanelAgentRun.js:541` start catch 只更新状态；`aiPanelAgentWorkspace.js:593` 等待流程依赖事件。
    - 风险：401/404/网络失败后生成态长期卡住。
    - 建议：设置最大重试和总超时，并进入明确失败态。

25. **EventSource 备用通道会漏掉新增事件类型**
    - 证据：`AgentRunEndpoints.cs:847` 后端写 named event；`aiPanelAgentRun.js:54` 使用硬编码事件类型表；`aiPanelAgentRun.js:238` 逐个 addEventListener；`aiPanelAgentRun.js:247` 只用默认 message 兜底。
    - 风险：后端扩展事件后备用通道无感知。
    - 建议：使用默认 `message` 包装事件，或版本化同步事件类型表。

26. **Plan public event 去重粒度过粗**
    - 证据：`AgentRunEndpoints.cs:533` 遍历公开事件；`AgentRunEndpoints.cs:678-679` key 只有 `eventType:stage:status`。
    - 风险：同阶段同状态的多条诊断被静默丢弃。
    - 建议：使用 public event id/序号，或纳入 title、summary、payload hash。

27. **CanBuild=false 和 BlockingReasons 没有阻止构建**
    - 证据：`VisionAgentPlanContracts.cs:34` 定义 `CanBuild`；`aiPanelAgentWorkspace.js:940` 渲染计划；`aiPanelAgentWorkspace.js:1371` 显示构建入口；`aiPanelAgentWorkspace.js:1442` 启动构建时只检查 generating/plan。
    - 风险：阻断计划仍可进入构建。
    - 建议：UI 禁用构建按钮并展示 blocking reasons，后端也校验 BuildFromPlan 快照。

28. **AgentRun 失败路径没有复用 manualRetry 契约**
    - 证据：`aiPanel.js:841-850` 旧路径生成重试草稿；`aiPanelAgentRun.js:793-803` 固定 `manualRetry: null`。
    - 风险：失败修复体验和状态不同步。
    - 建议：把 `run.failed` payload 归一到 `_handleResult` 同一 failure/manualRetry 结构。

29. **AgentRun 成功结果不回写持久化 sessionId**
    - 证据：`aiPanel.js:753` 旧路径保存 session；`aiPanelAgentWorkspace.js:1977-1989` AgentRun 只写 currentResult；`aiPanelAgentRun.js:838` 历史依赖 `this.sessionId`。
    - 风险：新会话历史和后续上下文丢失。
    - 建议：terminal 成功时同步 `this.sessionId` 并保存，后端构建器也补齐会话持久化。

30. **首事件超时会中断健康但空闲的 SSE**
    - 证据：`aiPanelAgentRun.js:163` 连接后启动 10 秒首事件计时；`aiPanelAgentRun.js:371` 超时；`aiPanelAgentRun.js:378` abort；`AgentRunEndpoints.cs:265` 后端读取 live events，无 heartbeat。
    - 风险：长阶段被误判为流失败并降级轮询。
    - 建议：后端发送 heartbeat，或将首事件超时改为连接失败/总 idle 策略。

31. **回放轮询每 1.5 秒拉全量事件**
    - 证据：`aiPanelAgentRun.js:77` 设置 `AGENT_RUN_REPLAY_INTERVAL_MS = 1500`；`aiPanelAgentRun.js:285` GET replay；`aiPanelAgentRun.js:293` 客户端过滤；`AgentRunEventStreamService.cs:242` replay 返回全量事件。
    - 风险：长 run 的网络和主线程成本线性增长。
    - 建议：给 replay API 加 `afterSequence`/分页，只返回增量和 gap 信息。

32. **AgentRun SSE 订阅通道无界**
    - 证据：`AgentRunEventStreamService.cs:188` 为每个订阅创建 unbounded channel；`AgentRunEventStreamService.cs:116` 对订阅者 `TryWrite`。
    - 风险：慢客户端或断连检测滞后时可能堆积内存。
    - 建议：改为 bounded channel，定义溢出策略，合并低价值状态事件并主动关闭滞后订阅。

33. **httpClient 的 PUT/DELETE 缺少自动端口发现兜底**
    - 证据：`core/messaging/httpClient.js:245-267` GET 有端口发现重试；`httpClient.js:311-337` POST 有重试；`httpClient.js:417-424` PUT 直接 fetch；`httpClient.js:430-436` DELETE 直接 fetch。
    - 风险：WebView/file 环境下服务端口变化时，写入/删除接口比 GET/POST 更容易失败。
    - 建议：抽取统一请求方法，所有 HTTP 动词共享端口发现、错误包装和保存端口逻辑。

34. **Inspection SSE 只解析 Header 游标，不支持 query afterSequence**
    - 证据：`InspectionEventEndpoints.cs:151-160` 只读 `Last-Event-ID`；前端 `inspectionSseClient.mjs:1-7` 也只构建 header。
    - 风险：无法设置 header 的 EventSource 或代理环境难以恢复断点。
    - 建议：与 AgentRun 一样支持 `lastEventId`/`afterSequence` query。

## 后端逻辑、并发与资源生命周期

35. **RuntimeHost 停止超时状态会被 finalize 覆盖**
    - 证据：`RuntimeHost.cs:316-318` 停止超时将状态置为 `Faulted` 并设置 `_stopTimeoutPending`；`RuntimeHost.cs:625-630` finalize 在 `_stopTimeoutPending` 为 true 时又恢复为 `Loaded/Idle`。
    - 风险：停止超时被隐藏，Studio/Station 看到“已加载”而不是故障。
    - 建议：为 stop timeout 保留独立终态，或 finalizer 不清除超时 Faulted，需显式 reset。

36. **RuntimeHost 事件回调未隔离订阅者异常**
    - 证据：`RuntimeHost.cs:559` 直接 `ResultAvailable?.Invoke(result)`；`RuntimeHost.cs:729` 直接 `SnapshotChanged?.Invoke`；`RuntimeHost.cs:734` 直接 `LogMessage?.Invoke`。
    - 风险：任一订阅者抛异常会反向破坏结果持久化、加载或停止流程。
    - 建议：复制委托列表，逐个 try/catch，必要时异步投递事件。

37. **取消/故障路径可能无限等待结果写入队列**
    - 证据：`RuntimeHost.cs:515` 和 `RuntimeHost.cs:530` 使用 `CancellationToken.None` 持久化取消/失败结果；结果写入端可能在 bounded channel 等待。
    - 风险：文件 IO 卡住或消费者停滞时，取消/故障记录反而挂住运行线程。
    - 建议：故障记录使用短超时、TryWrite 降级或死信记录，不用无限 token。

38. **实时检测启动失败回滚使用请求 token**
    - 证据：`InspectionService.cs:317` 已注册 session；`InspectionService.cs:337` 回滚 `TryStopAsync(projectId, cancellationToken)` 仍用外部请求 token。
    - 风险：HTTP 请求取消时回滚也取消，Coordinator 可能停在 Starting，后续启动被挡。
    - 建议：回滚用内部短超时或 `CancellationToken.None`，并保证失败清理幂等。

39. **InspectionWorker 先启动后台任务再登记状态**
    - 证据：`InspectionWorker.cs:198` 先 `Task.Run`；`InspectionWorker.cs:214` 才 `TryAdd`；`InspectionWorker.cs:228` 才增加指标。
    - 风险：任务快速退出时 cleanup 可早于指标增加，活跃 worker 计数和生命周期状态错乱。
    - 建议：先登记 entry/指标，再释放启动门闩让后台任务运行。

40. **Coordinator 在锁内同步触发 StateChanged**
    - 证据：`InspectionRuntimeCoordinator.cs:57`、`:98`、`:134`、`:303` 等状态迁移路径同步触发事件。
    - 风险：订阅者重入会卡在同一 `SemaphoreSlim`；订阅者异常会中断状态迁移。
    - 建议：锁内只构造事件参数，释放锁后逐订阅者安全通知。

41. **结果后台持久化在 spool 失败时不释放预算**
    - 证据：`InspectionResultBackgroundService.cs:172` 保存 batch；`InspectionResultBackgroundService.cs:230` append spool 可能抛异常；`InspectionResultBackgroundService.cs:188` 外层只记录日志。
    - 风险：DB 与 spool 同时异常时 batch 留存，`_queuedImageBytes` 不释放，生产端长期背压。
    - 建议：对 spool 写失败设置死信/丢弃策略并释放预算，或进入受控降级状态。

42. **图片持久化队列停机超时后直接丢剩余图片**
    - 证据：`QueuedInspectionImagePersistenceService.cs:120` 完成 writer；`:130` 只等 5 秒；`:141` 然后取消。
    - 风险：慢盘或大量 NG 图停机时无 durable spool，审计证据丢失。
    - 建议：增加图片 spool/manifest，或报告明确丢弃计数并允许配置 drain 策略。

43. **CameraFrameStreamCoordinator 的 IdleStopCts 使用不同锁保护**
    - 证据：`CameraFrameStreamCoordinator.cs:128` 在 `Gate` 下改；`:690` stop 中改；`:710` 在 `lock(entry)` 下改。
    - 风险：双重 Dispose、丢失 idle stop、生产者泄漏或偶发 ObjectDisposed。
    - 建议：统一由 `Gate` 或单独私有锁管理 CTS 生命周期。

44. **相机 producer gate 被多路径 Dispose**
    - 证据：`CameraFrameStreamCoordinator.cs:229`、`:356`、`:433`、`:719` 多处释放 producer gate。
    - 风险：idle-stop、Dispose、Acquire/Release 交错时可能等待已释放 semaphore；后台 idle 任务也未集中取消/等待。
    - 建议：producer entry 增加生命周期 CTS/refcount，gate 延迟到 coordinator Dispose 统一释放。

45. **TCP 通讯连接池无上限/空闲回收，超时后仍复用连接**
    - 证据：`TcpCommunicationOperator.cs:41-44` 静态池；`:139-140` 加入池；读写超时路径没有强制 `InvalidateConnection`。
    - 风险：多目标地址长期积累 socket；读写超时后的半脏连接继续被复用。
    - 建议：增加容量、idle TTL 和清理入口；操作超时一律移除并关闭连接。

46. **PLC 客户端复用只保护建连，不保护读写/心跳**

## 性能隐患

51. **WinForms 日志追加是 O(n) 拷贝**
    - 证据：`ClearVision.Product/src/ClearVision.Product.Station/MainForm.cs:1147` 的 `AppendLog` 每条日志读取 `_logTextBox.Lines.ToList()`，再 `Lines = lines.ToArray()`。
    - 风险：高频日志会反复复制整个文本框内容并触发 UI 重排。
    - 建议：改为 `AppendText`，维护环形缓冲或按定时器批量刷新。

52. **Station spool 在锁内重写整份 JSONL**
    - 证据：`StationSpoolStore.cs:166` ack 后 `RewriteSpoolLocked()`；`StationSpoolStore.cs:296` 重写文件；`StationCommandResultSpoolStore.cs:55` 每次 enqueue 也 rewrite。
    - 风险：结果/命令频繁时磁盘写放大，锁持有时间随 pending 数增长。
    - 建议：追加日志加 checkpoint/compact，或用 SQLite/轻量队列表。

53. **串口算子固定同步阻塞 100ms**
    - 证据：`SerialCommunicationOperator.cs:87`、`:125`、`:131` 的执行路径同步 Open/Write/Read，并 `Thread.Sleep(100)`。
    - 风险：每次执行至少占用线程 100ms，拖慢高频流水线。
    - 建议：使用异步串口读写、可配置响应等待、复用端口或独立通信 worker。

54. **变量算子每次循环打 Information 日志**
    - 证据：`VariableReadOperator.cs:78`、`VariableWriteOperator.cs:103`、`VariableIncrementOperator.cs:93` 每次执行都 `LogInformation`。
    - 风险：变量节点通常在每帧路径上，日志吞吐和格式化成本会放大。
    - 建议：降到 Debug/Trace，或加采样、变化才记录、诊断开关。

55. **StatisticsOperator 每次复制窗口并多次遍历**
    - 证据：`StatisticsOperator.cs:58`、`:73`、`:81`、`:87` 对窗口 `ToArray()` 后 `Average/Min/Max/Select.Sum`。
    - 风险：窗口最大 50,000，高频测量节点会形成 O(window) CPU 与分配。
    - 建议：维护 rolling sum/min/max/variance，必要时用单调队列或分段统计。

56. **FrameAveraging 每帧克隆并重算全窗口**
    - 证据：`FrameAveragingOperator.cs:57`、`:75`、`:82`、`:208` 每次 `src.Clone()` 入队，窗口 `ToArray()`，均值模式遍历所有帧。
    - 风险：大图和 64 帧窗口下内存带宽、GC、Mat 分配压力高。
    - 建议：均值模式维护滚动累加 Mat，帧出队时减旧帧。

57. **ShapeMatching NMS 二次复杂度且反复分配**
    - 证据：`ShapeMatchingOperator.cs:1047` 排序候选；`:1058` 循环处理；`:1063` 每轮 `Where(...).ToList()`。
    - 风险：候选多时 O(n^2) 且大量临时 List。
    - 建议：用索引数组/标记删除，或网格/空间索引预筛 IoU。

58. **Undistort 缓存 unmanaged Mat 但无释放入口**
    - 证据：`VisionRuntimeServiceCollectionExtensions.cs:67` 注册算子；`UndistortOperator.cs:21-24` 持有 `_mapCache`；`UndistortOperator.cs:172` 仅 eviction 时 Dispose。
    - 风险：进程生命周期内最多 16 组 remap Mat 常驻，服务关闭也不会显式释放。
    - 建议：实现 `IDisposable` 清空缓存，或改用集中 Mat/LUT 缓存服务并统计容量。

59. **文件输出算子在执行线程做同步磁盘 I/O**
    - 证据：`ImageSaveOperator.cs:131` 调用 `Cv2.ImWrite`；`TextSaveOperator.cs:187`、`:194` 直接 `File.AppendAllText/WriteAllText`。
    - 风险：慢盘/网络盘会阻塞流程执行线程。
    - 建议：提供异步落盘队列、批量写、背压和失败重试策略。

60. **DatabaseWrite 每条记录打开连接且表锁缓存无回收**
    - 证据：`DatabaseWriteOperator.cs:39` 静态缓存；`:235` 创建连接；`:308` 打开连接。
    - 风险：动态表/连接串会累积 semaphore；高频写入有连接开销和 DB 往返。
    - 建议：限制/回收表缓存，复用连接或批量写入，表初始化移到启动/配置阶段。

61. **PLC 心跳全局 1 秒顺序巡检所有连接**
    - 证据：`PlcCommunicationOperatorBase.cs:53` 心跳间隔；`:189`、`:197` 遍历快照；`:219` ping。
    - 风险：连接多或设备慢时巡检占用后台资源并和业务连接竞争。
    - 建议：按连接活动度自适应心跳、并发限流、空闲连接回收，并配置化。

62. **Station 主窗体状态刷新可能阻塞 UI**
    - 证据：`MainForm.cs:112` WinForms timer；`MainForm.cs:1167`、`:1277` 刷新状态；`PlcCommunicationOperatorBase.cs:110` 快照方法同步 `_poolLock.Wait(50)`。

63. **前端自动保存同步序列化整张流程图**
    - 证据：`app.js:182` 自动保存间隔；`app.js:1750` 保存流程；`app.js:218` 写 localStorage；`flowCanvas.js:1685` 序列化流程图。
