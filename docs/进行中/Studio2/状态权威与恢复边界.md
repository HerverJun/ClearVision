# Studio 2.0 状态权威与恢复边界

> 状态：G00 基线文档
> 日期：2026-07-01
> 依据分支：`codex初稿`
> 依据 SHA：`58c7569958f3bf8ab627f5c5b76ff0a77cc86914`

本文件定义 Studio 2.0 后续工作必须遵守的状态边界。它不新增运行时契约，只把当前代码中的权威关系固定为基线。

## AgentRun 与运行事件权威

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/AgentRun/AgentRunEventStore.cs`
- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/AgentRun/AgentRunEventStreamService.cs`
- `ClearVision.Product/src/ClearVision.Product.Desktop/Endpoints/AgentRunEndpoints.cs`

权威关系：

- `AgentRunEventStore` 是 AgentRun 运行事件和摘要的持久化权威，存储文件为 `agent_run_events.jsonl` 与 `agent_run_summary.jsonl`。
- `AgentRunEventStreamService` 是内存运行态、SSE 订阅、终态预约、终态提交和 replay 的服务入口；它从 EventStore 恢复 state。
- AgentRun 事件为 metadata-only，并经 `AgentRunEventRedactor` 脱敏后写入。
- Studio 2.0 不得建立第二套 AgentRun 事件日志、第二套 run 状态机或独立终态判断。

## Terminal Projector 与 Session 投影

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/Agent/VisionAgentBuildTerminalProjector.cs`
- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/ConversationalFlowService.cs`

权威关系：

- `VisionAgentBuildTerminalProjector` 只处理 Build terminal outcome 到 `ConversationSession` 的投影。
- 投影写入 assistant turn、`CurrentFlowJson`、`CurrentCanvasFlowJson` 和 `VisionAgentWorkspaceSnapshot`。
- 投影前必须经 `VisionAgentBuildProjectionJournal.Begin()`，投影成功后标记 `projected`，失败标记 `failed`。
- `ConversationSession` 是会话投影，不是 Project/Flow/GlobalVariables 的正式保存权威。

## Projection Journal 的恢复职责

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/Agent/VisionAgentBuildProjectionJournal.cs`
- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/Agent/VisionAgentBuildProjectionReconciliationService.cs`
- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/Agent/VisionAgentBuildProjectionDispositionResolver.cs`

权威关系：

- `VisionAgentBuildProjectionJournal` 保存 Build terminal projection checkpoint，存储文件为 `agent_run_build_projections.jsonl`。
- Journal 记录 `pending/projected/failed`、terminal mutation id、payload fingerprint、expected workspace revision 和 identity。
- Journal 用于幂等恢复和 metadata conflict 判断，不持有正式 Project/Flow 数据。
- `VisionAgentBuildProjectionReconciliationService` 启动时读取 terminal AgentRun 事件，并只在 disposition 为 `Project` 时调用 projector 恢复投影。

## Workspace Snapshot 的角色

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/ConversationalFlowService.cs`
- `ClearVision.Product/src/ClearVision.Product.Infrastructure/AI/Agent/VisionAgentRunRecoveryReconciliationService.cs`
- `ClearVision.Product/src/ClearVision.Product.Desktop/Endpoints/AgentRunEndpoints.cs`

权威关系：

- `VisionAgentWorkspaceSnapshot` 是 `ConversationSession` 内的 Plan/Build 工作台快照，字段包括 lifecycle、PlanRun、BuildRun、terminal sequence、confirmed answers 和 submitted build fingerprint。
- Snapshot 通过 revision、client mutation id、payload fingerprint 和 mutation receipt 实现幂等与冲突判断。
- `VisionAgentRunRecoveryReconciliationService` 启动时用 AgentRun replay 和 workspace snapshot 修复未终态、终态不一致或 host interrupted 状态。
- Snapshot 不等同于正式工程保存，不应被 Studio 2.0 用作 Project、Flow 或 GlobalVariables 的最终业务源。

## Project、Flow、GlobalVariables 的正式保存权威

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Application/Services/ProjectService.cs`
- `ClearVision.Product/src/ClearVision.Product.Application/Services/ProjectSaveCoordinator.cs`
- `ClearVision.Product/src/ClearVision.Product.Desktop/Endpoints/ApiEndpoints.cs`
- `ClearVision.Product/src/ClearVision.Product.Desktop/wwwroot/src/features/project/projectManager.js`
- `ClearVision.Product/src/ClearVision.Product.Desktop/wwwroot/src/features/global-variables/globalVariablePanel.js`

权威关系：

- 后端正式入口是 `ProjectService`，外部 HTTP 入口是 `/api/projects/*`。
- `ProjectService.UpdateAsync()` 通过 `ProjectSaveCoordinator.SaveExistingProjectAsync()` 同步保存 Project metadata、Flow JSON 和 GlobalVariables schema。
- `ProjectService.UpdateFlowAsync()` 最终仍回到 `UpdateAsync()`。
- `ProjectService.UpdateGlobalVariablesAsync()` 最终仍回到 `UpdateAsync()`。
- 前端 `projectManager.saveProject()` 只是调用后端 API，不是保存权威。
- 前端 `globalVariablePanel.js` 只编辑 schema 草稿并调用 `projectManager.saveGlobalVariables()` 写入后端。

## ProjectSaveCoordinator 事务边界

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Application/Services/ProjectSaveCoordinator.cs`
- `ClearVision.Product/src/ClearVision.Product.Desktop/Program.cs`

权威关系：

- `ProjectSaveCoordinator` 是 Project/Flow/VariableState 跨存储保存的事务边界。
- 保存参与者为 `Project`、`Flow`、`VariableState`。
- manifest 阶段为 `Prepared -> CommitIntended -> Completed`。
- Project 访问通过项目级 `SemaphoreSlim` gate 串行化。
- Desktop 启动时调用 `RunStartupRecoveryAsync()`，在服务可用前完成 transaction root 恢复或标记项目需要恢复。
- Studio 2.0 不得绕过 `ProjectSaveCoordinator` 直接写 Project repository、flow file 或 variable state。

## 前端状态边界

已验证代码：

- `ClearVision.Product/src/ClearVision.Product.Desktop/wwwroot/src/app.js`
- `ClearVision.Product/src/ClearVision.Product.Desktop/wwwroot/src/features/project/projectManager.js`

边界：

- 当前旧前端仍由 `app.js` 作为入口，本轮没有引入 Vue、Vite、Pinia 或 TypeScript 工作台。
- `flowRevision` 是 UI 本地 revision 线索；正式持久化身份以后端 `PersistenceRevision` 为准。
- `localStorage` 中 `cv_autosave_backup` 是本机草稿备份，只能辅助恢复 UI 草稿；恢复后仍需调用正式保存 API。
- 前端状态、未来 Pinia store、DOM 和执行包文件均不能成为 Project、Flow、GlobalVariables 或 Agent 的业务权威。

## Studio 2.0 后续约束

- G01 及后续 Goal 只能复用上述权威，不得建立第二套 Agent、Project 或 Flow command bus。
- 新增状态机、feature flag 或迁移白名单必须在对应 Goal 中登记 owner、关闭条件和回退边界。
- Result Inspector、Visual Scene、Geometry、Spatial、Calibration 等后续能力只能消费正式后端投影或草稿边界，不得把前端缓存提升为权威。
