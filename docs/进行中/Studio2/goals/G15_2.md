## Preview Panel 现状审计

旧 owner：
`app.js` 创建唯一 `NodePreviewCoordinator`；flag off 下 `initializeNodePreviewExperience()` 根据 `Studio:NodePreviewInspectorEnabled` 创建 `NodePreviewOverlay` 或 `NodePreviewInspector`；legacy `PropertyPanel` 在 `initPreviewPanel()` 中创建嵌入式 `PreviewPanel`，在 ROI 支持节点上创建 `RoiEditorPanel`。

旧 mount 位置：
`NodePreviewOverlay` / `NodePreviewInspector` 挂载到 `.flow-editor-container`；legacy `PreviewPanel` 挂载到 `PropertyPanel` 渲染出的 `#operator-preview-container`；legacy `RoiEditorPanel` 挂载到 `#roi-editor-container`。

旧 subscription：
`NodePreviewCoordinator` 订阅 `flowCanvas.subscribeStructureState()` 并在结构变化时 invalidate preview；legacy `PreviewPanel` 订阅 `previewCoordinator.subscribe()` 和 `subscribeStructureState()`；`NodePreviewOverlay` 订阅 `previewCoordinator.subscribe()` 与 `flowCanvas.subscribeViewState()`；`RoiEditorPanel` 订阅 `previewCoordinator.subscribe()`；legacy `PropertyPanel` owner 订阅 `subscribeSelectedOperator()`。

旧 timer/debounce：
`NodePreviewCoordinator` 持有 `pendingTimer` debounce、preview timeout `setTimeout` 和 `AbortController`；legacy `PreviewPanel.scheduleAutoPreview()` 触发 coordinator debounce；legacy `PropertyPanel.showToast()` 使用短时 `setTimeout`；`RoiEditorPanel` 无常驻 timer，但有 async apply generation 防 stale。

旧 preview request entry：
selection 进入 `flowCanvas.onNodeSelected()` 后调用 `nodePreviewCoordinator.setActiveNode(node)`；manual/auto refresh 由 `PreviewPanel.refresh()` / `scheduleAutoPreview()`、`NodePreviewOverlay` refresh、`flowCanvas.runNode()` 进入 `NodePreviewCoordinator.requestActivePreview()`，最终调用 `inspectionController.previewNode(nodeId, options)`。

旧 artifact read entry：
preview image artifacts 由 `NodePreviewCoordinator.resolveArtifactImages()` 通过内部 `artifactClient.getPreviewArtifactBlob()` 读取并创建 object URL；G13X 模块结果面板的按需 artifact 摘要由 `PreviewPanel.readArtifactPreview()` 调 `previewCoordinator.readArtifactForCurrentState()`，不直接 `fetch()` 或引入 `httpClient`。

旧 overlay / ROI / Scene 入口：
`NodePreviewOverlay` 只消费 coordinator presenter 并定位到 FlowCanvas 节点；`RoiEditorPanel` 复用现有 `ImageCanvas`，用 coordinator input preview image 做 ROI 编辑背景；G13X Scene/模块结果通过 `operatorResultViewModel.mjs` 只读解析 observation `visualScene`，不创建第二 Scene renderer。

旧 destroy/dispose：
`NodePreviewCoordinator.destroy()` 清 debounce、abort、structure subscription、listeners、artifact object URL/server artifact；`PreviewPanel.destroy()` abort artifact read、unsubscribe preview/structure、清图片引用；`NodePreviewOverlay.destroy()` unsubscribe preview/view 并移除 root；`RoiEditorPanel.destroy()` unsubscribe preview、destroy `ImageCanvas`；legacy `PropertyPanel.destroy()` destroy preview/ROI/calibration 子面板并解绑 FilePickedEvent。

依赖 FlowCanvas 的方式：
`app.js` 直接持有 raw `flowCanvas` 并创建 `FlowCanvasAdapter`；legacy preview selection 通过 raw `flowCanvas.onNodeSelected()` 触发 coordinator；`PreviewPanel` / `RoiEditorPanel` 通过 `serviceRegistry.get('flowCanvasAdapter') || serviceRegistry.get('flowCanvas')` 获取 nodes、revision、selectNode、structure subscription。

依赖 selected node 的方式：
`flowCanvas.onNodeSelected()` 构造 selected operator signal 给 PropertyPanel，同时调用 `nodePreviewCoordinator.setActiveNode(node)`；legacy `PropertyPanel` 订阅 `subscribeSelectedOperator()` 并把 `currentOperator` 传给 `PreviewPanel` / `RoiEditorPanel`。

依赖 PreviewCoordinator 的方式：
`PreviewPanel` 展示 `previewCoordinator.getState()/subscribe()`，manual/auto preview 只调用 `requestActivePreview()`，G13X artifact 摘要只调用 `readArtifactForCurrentState()`；`RoiEditorPanel` 只读 input image state；`NodePreviewOverlay` 展示 presenter 并触发 coordinator refresh。

G13X operator result panel 入口：
legacy 入口在 `previewPanel.js` 内部的 `#operator-result-panel`，纯 view-model 为 `operatorResultViewModel.mjs`；它继续复用同一个 `NodePreviewCoordinator` state 与 `readArtifactForCurrentState()`，不新增 artifact client、ImageCanvas 或 Scene renderer。

是否触碰正式 history/evidence：
现状没有把 preview state、PreviewArtifact、`ExecutionObservationEnvelopeV1` 持久化到正式 Inspection history、G14A/G14B/G14C evidence/compare/export；preview artifacts 仍是 Desktop-only 临时资源。
