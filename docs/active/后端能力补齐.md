# 结果面板 (Results Panel) 后端功能补齐计划

> 配合前端 Phase 3 工业看板升级，以下 API 和数据结构需要后端支持。

---

## 1. KPI 涨跌幅对比

**场景**：看板头部 6 张 KPI 卡片需要显示"较昨日"的涨跌幅（如 +5.2%、-1.5%）。

**建议 API**：
```http
GET /api/v1/analytics/kpi-comparison?projectId={id}&timeRange=today&compareTo=yesterday
```

**返回结构**：
```json
{
  "total": { "value": 12345, "change": 5.2, "changeType": "up" },
  "ok": { "value": 11890, "change": 6.1, "changeType": "up" },
  "ng": { "value": 420, "change": -1.5, "changeType": "down" },
  "error": { "value": 35, "change": -0.8, "changeType": "down" },
  "yieldRate": { "value": 96.5, "change": 0.8, "changeType": "up" },
  "avgTime": { "value": 1200, "change": -100, "changeType": "down", "unit": "ms" }
}
```

**实现要点**：
- 需要同时查询当前时间范围和上一周期的统计数据
- 若数据不足，可返回 `change: null`，前端显示 `--`

---

## 2. 生产线与节点信息

**场景**：看板标题需要显示"2号生产线 视觉质检节点 A-04"。

**建议方案 A（推荐）**：从现有工程配置中读取
- 在 `Project` 或 `Flow` 配置中增加 `productionLine` 和 `stationId` 字段
- 前端通过已有工程上下文直接获取，无需新 API

**建议方案 B**：
```http
GET /api/v1/projects/{projectId}/production-config
```

**返回结构**：
```json
{
  "lineName": "2号生产线",
  "stationName": "视觉质检节点 A-04"
}
```

---

## 3. 缺陷特征雷达图数据

**场景**：雷达图展示 5 个维度（划伤、脏污、缺角、气泡、其他）的相对分布。

**建议 API**：
```http
GET /api/v1/analytics/defect-radar?projectId={id}&timeRange=today
```

**返回结构**：
```json
{
  "dimensions": ["划伤", "脏污", "缺角", "气泡", "其他"],
  "values": [0.85, 0.60, 0.90, 0.40, 0.55],
  "maxValue": 1.0
}
```

**实现要点**：
- `values` 为归一化后的 0~1 浮点数
- 若某维度无数据，可返回 0.15 作为基线值
- 可复用现有的 `/analysis/defect-distribution` 接口，只需增加归一化和维度映射

---

## 4. 吞吐量时序数据

**场景**：面积图展示按小时的检测量趋势（如 08:00~16:00）。

**建议 API**：
```http
GET /api/v1/analytics/throughput?projectId={id}&interval=Hour&timeRange=today
```

**返回结构**：
```json
[
  { "timestamp": "2025-04-23T08:00:00Z", "count": 120 },
  { "timestamp": "2025-04-23T09:00:00Z", "count": 145 },
  { "timestamp": "2025-04-23T10:00:00Z", "count": 98 }
]
```

**实现要点**：
- 可复用现有的 `/analysis/trend/{projectId}` 接口
- 需要在 `DataPoint` 中增加 `totalCount`（该时间段内的总检测量）
- 当前 `trend` 接口返回的是 `ngCount`/`errorCount`，建议扩展为同时返回 `totalCount`

---

## 5. 高级统计数据

**场景**：底部 3 张卡片展示 CPK、MTBF、缺陷聚类核心特征。

**建议 API**：
```http
GET /api/v1/analytics/advanced?projectId={id}&timeRange=today
```

**返回结构**：
```json
{
  "cpk": {
    "value": 1.52,
    "change": 0.05,
    "grade": "A+"
  },
  "mtbf": {
    "value": 480,
    "unit": "h",
    "change": 12,
    "changeUnit": "h"
  },
  "defectCluster": {
    "topRegion": "左上边缘划伤",
    "confidence": 0.92,
    "clusterCount": 3
  }
}
```

**实现要点**：
- **CPK**（制程能力指数）：需要历史 OK/NG 数据计算标准差和均值
- **MTBF**（平均无故障时间）：需要设备运行日志和故障记录
- **缺陷聚类**：需要基于缺陷坐标/类型做简单聚类分析（K-Means 或 DBSCAN），返回最高频的缺陷区域描述

---

## 6. 报表生成（已有占位符）

**场景**：用户点击"生成深度报告"按钮，生成带图表的 PDF 报告。

**建议 API**：
```http
POST /api/v1/reports/generate
Content-Type: application/json

{
  "projectId": "xxx",
  "timeRange": "today",
  "includeCharts": true,
  "format": "pdf"
}
```

**返回结构**：
```json
{
  "reportId": "uuid",
  "downloadUrl": "/api/v1/reports/download/uuid",
  "expiresAt": "2025-04-23T12:00:00Z"
}
```

**实现要点**：
- 可使用 iText / QuestPDF / Puppeteer 等库生成 PDF
- 报告应包含：KPI 汇总、良率仪表盘截图、雷达图、吞吐量趋势、高级统计、原始结果列表

---

## 7. 实时数据推送（已有占位符）

**场景**：看板右上角状态显示"监控运行中"，需要定时刷新数据。

**建议方案 A（轮询）**：
- 前端每 30 秒轮询 `GET /api/v1/analytics/kpi-comparison` 和 `GET /api/v1/analytics/advanced`
- 实现简单，但实时性一般

**建议方案 B（SignalR WebSocket）**：
```csharp
// Hub 端点: /hub/inspection-results
hubConnection.on('ReceiveNewResult', (result) => { ... });
hubConnection.on('KpiUpdated', (kpiData) => { ... });
```
- 每次新检测结果到达时，主动推送更新的 KPI 和图表数据
- 前端无需轮询，实时性最佳

---

## 优先级建议

| 优先级 | 功能 | 影响范围 |  estimated effort |
|--------|------|----------|-------------------|
| P0 | KPI 涨跌幅 | 6 张卡片显示 | 低（复用现有统计接口） |
| P0 | 吞吐量时序 | 面积图数据 | 低（扩展 trend 接口） |
| P1 | 缺陷雷达图 | 雷达图数据 | 低（复用 defect-distribution） |
| P1 | 生产线信息 | 标题显示 | 极低（配置字段） |
| P2 | 高级统计 (CPK/MTBF) | 底部 3 张卡片 | 中（需要新计算逻辑） |
| P2 | 缺陷聚类 | 底部卡片 + 雷达图 | 中（需要聚类算法） |
| P3 | 实时推送 | 状态刷新 | 中（SignalR Hub） |
| P3 | PDF 报告生成 | 导出功能 | 高（PDF 渲染引擎） |

---

## 前端当前兜底策略

在以上后端 API 未就绪前，前端已做以下处理：
- KPI 涨跌幅显示静态 Mock 数据（可在 `renderKPIs` 中关闭）
- 仪表盘、雷达图、面积图在无数据时显示默认 Mock 形状
- 高级统计卡片显示 Mock 数据（CPK 1.52 / MTBF 480h / 缺陷聚类）
- 所有占位数据均有 `id` 绑定，后端 API 对接后只需替换数据源即可自动刷新
