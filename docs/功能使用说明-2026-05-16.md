# ClearVision 功能使用说明（2026-05-16）

## 1. 说明范围

本文面向 ClearVision Studio 的日常使用者、视觉工程师、现场联调工程师和项目维护者，说明当前版本中主要功能的入口、使用步骤、数据流和注意事项。

当前版本的核心形态是：

- Windows 桌面 Studio：WinForms + WebView2。
- 本地运行时 API：Desktop 内嵌 ASP.NET Core endpoints。
- 工业视觉流程：项目、流程画布、算子、模板、图像预览和检测执行。
- 现场链路：Runtime Package 导出、Station 同步、结果摘要、健康状态和部署命令。
- 质量体系：算子目录、质量矩阵、性能报告、CI gate 和 OperatorLibrary 包。

本文不把占位、内部能力或未接入能力写成可交付功能。遇到“暂未接入”“内部能力”“未开放”状态时，请按界面提示处理。

## 2. 使用前准备

### 2.1 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| .NET SDK | 仓库 `global.json` 指定的 SDK |
| 桌面运行 | Microsoft Edge WebView2 Runtime |
| 脚本环境 | PowerShell |
| UI/Playwright 测试 | Node.js 20，仅测试时需要 |
| 本地数据库 | SQLite，由 Studio 初始化 |

### 2.2 启动 Studio

在仓库根目录执行：

```powershell
dotnet restore .\Acme.Product\Acme.Product.sln --locked-mode
dotnet build .\Acme.Product\Acme.Product.sln --configuration Debug --no-restore
dotnet run --project .\Acme.Product\src\Acme.Product.Desktop\Acme.Product.Desktop.csproj --configuration Debug --no-build
```

启动后，桌面壳会加载 WebView2 前端，并连接内嵌本地 API。若前端提示 API 未连接，先检查桌面进程是否正常启动、本地端口是否被占用，以及 WebView2 Runtime 是否安装。

### 2.3 首次登录和管理员初始化

首次使用通常需要初始化管理员账号。

1. 打开 Studio。
2. 如果系统提示尚未设置管理员，进入初始化页面。
3. 输入管理员用户名、显示名和密码。
4. 初始化完成后使用该账号登录。
5. 之后普通用户由管理员在“设置 / 用户管理”中创建。

权限说明：

- 普通用户可查看和使用多数业务功能。
- 管理员可管理用户、系统配置、AI 模型、PLC 配置、Station 命令、运行包部署等高风险功能。
- Station 命令、Station 身份更新、部署包和测试包接口当前需要 Admin 权限。

## 4. 项目管理

### 4.1 新建空白项目

1. 进入“项目”视图。
2. 点击新建项目。
3. 输入工程名称和可选描述。
4. 选择空白项目。
5. 创建后进入流程编辑。

建议命名方式：

- 使用产线、工位、产品和检测类型组合，例如 `LineA-Terminal-WireSequence`。
- 避免使用仅有日期或临时编号的名称，后续导出运行包和结果追溯会不清晰。

### 4.2 创建示例工程

当前 Demo 工程创建已接入正式入口。

1. 进入“项目”视图。
2. 点击“示例工程”或在新建项目弹窗中选择示例工程。
3. 可选择完整引导版或简化版。
4. 创建后打开工程，查看预置流程、算子和参数。

使用建议：

- 第一次熟悉产品时优先使用示例工程。
- 示例工程适合演示工作流和 UI，不应直接作为现场项目交付。
- 现场项目前应替换真实图像、真实模型、真实 ROI 和业务规则。

### 4.3 打开、搜索和删除项目

项目列表支持查看已有项目、最近打开项目和按关键字搜索。删除项目前请确认：

- 项目是否已经导出运行包。
- 是否需要保留历史检测结果。
- 是否还有 Station 正在使用对应 flow/package。

### 4.4 导入和导出项目

项目导出适合在同一开发/调试环境之间传递项目结构。若要给 Station 或现场运行，请使用 Runtime Package 导出，不要只导出普通项目 JSON。

## 5. 流程编辑

### 5.1 基本概念

ClearVision 的检测流程由算子节点和连线组成。

| 概念 | 说明 |
|---|---|
| 算子 | 一个可执行处理单元，例如图像采集、阈值、模板匹配、深度学习、PLC 通信 |
| 输入端口 | 算子接收数据的位置 |
| 输出端口 | 算子产生数据的位置 |
| 参数 | 算子的配置项，例如阈值、ROI、模型路径、置信度 |
| 连线 | 把上游输出连接到下游输入 |
| 流程保存 | 将当前画布状态保存到项目 |

### 5.2 添加算子

1. 打开项目并进入流程编辑。
2. 在算子库搜索或展开分类。
3. 将算子拖入画布。
4. 选中算子，在属性面板配置参数。
5. 将算子的输出端口连接到下游输入端口。

建议从最小链路开始：

```text
ImageAcquisition -> 预处理/检测/测量 -> ResultJudgment -> ResultOutput
```

线序检测推荐链路：

```text
ImageAcquisition -> DeepLearning(OutputFormat=EndToEndNms) -> DetectionSequenceJudge -> ResultOutput
```

无触发信号的视频流场景推荐链路：

```text
ImageAcquisition(Continuous) -> FrameChangeTrigger -> DeepLearning(OutputFormat=EndToEndNms) -> DetectionSequenceJudge -> ResultOutput
```

### 5.3 连线规则

连接时注意：

- 输出端口类型应与输入端口类型匹配。
- 一个输入端口通常只接收一个上游来源。
- 图像类输出可继续接图像处理、检测、显示或保存算子。
- 布尔类输出适合连接条件判断、结果判定或通信写入。
- 数值类输出适合测量、统计、阈值判断或报表。

如果出现类型不匹配、端口占用或无效连接，请根据界面提示调整。

### 5.4 配置参数

选中算子后，在属性面板填写参数。常见参数类型：

| 类型 | 示例 | 使用说明 |
|---|---|---|
| 数值 | 阈值、置信度、核大小 | 保持在推荐范围内，现场调参要记录版本 |
| 布尔 | 是否启用、是否保存结果 | 用于开关类行为 |
| 枚举 | 模式、算法类型、触发方式 | 选择前确认下游语义 |
| 文件路径 | 模型、标签、标定文件 | 现场交付时必须确保文件存在 |
| ROI | X/Y/W/H、矩形/多边形区域 | 优先用真实图像调准 |
| 字符串 | 标签顺序、Topic、URL | 注意大小写和业务约定 |

### 5.5 ROI 设置

ROI 常用于：

- 限制检测范围。
- 过滤非目标区域误检。
- 聚焦测量区域。
- 现场到料检测。

配置建议：

1. 先用真实图像或样本图加载预览。
2. 在图像上确认产品区域。
3. 设置 ROI 后做单节点预览。
4. 对 OK/NG 样本都验证一次。
5. 将 ROI 参数记录到项目变更说明或场景包 manifest。

## 6. 算子库使用

### 6.1 算子分类

当前正式算子目录为 156 个，覆盖：

- 图像采集与预处理。
- 阈值、滤波、形态学、边缘、Blob。
- 模板匹配、特征匹配、定位。
- 几何测量、宽度、间隙、圆、线、点线距离。
- 标定、畸变校正、像素到世界坐标。
- AI 检测、语义分割、异常检测、表面缺陷。
- PLC、TCP、串口、HTTP、MQTT 等通信。
- 流程控制、变量、条件、结果输出。
- 3D 点云基础算子。

### 6.2 查看算子元数据

在算子库中选中算子后，可查看：

- 显示名、分类、描述。
- 输入输出端口。
- 参数定义。
- 图标和标签。
- 部分算子的调参建议或预览能力。

### 6.3 自动参数推荐和单节点预览

部分算子支持：

- 参数推荐：根据输入图像给出初始参数建议。
- 节点预览：只运行当前节点或局部节点，查看处理前后图像和输出数据。

使用建议：

- 推荐参数只作为起点，不等同于现场验收参数。
- 每次调参后用 OK/NG 样本验证。
- 预览通过后再连接到完整流程。

### 6.4 当前算子边界提醒

- `MqttPublish` 当前源码为 `placeholder-disabled`，会校验参数并快速失败，不能当作正式 MQTT 发布能力使用。
- `FrameChangeTrigger` 已进入正式目录，适合无触发信号的视频流到料门控；但仍应补足场景证据和参数边界验证后再用于强交付承诺。
- 模型相关算子必须绑定模型文件、标签契约、数据版本和硬件 profile，不能只靠 smoke 结果作为质量验收。

## 7. 图像、预览与调参

### 7.1 上传或选择图像

图像可用于：

- 节点预览。
- ROI 标定。
- 算子参数推荐。
- 单次检测调试。

注意事项：

- 图像尺寸越大，预览和检测耗时越长。
- 模型输入尺寸、颜色通道、归一化规则要与训练/导出约定一致。
- 现场样本不要随意提交到仓库，敏感样本应保留在外部数据目录，仅提交 manifest 或脱敏说明。

### 7.2 节点预览

操作步骤：

1. 在画布中选中算子。
2. 上传或选择一张测试图像。
3. 点击预览。
4. 查看前后图、输出字段、诊断信息和错误提示。
5. 调整参数后重复预览。

常见失败原因：

- 必填输入未连接。
- 图像为空或格式不支持。
- 模型路径不存在。
- 标签顺序与模型输出不匹配。
- ROI 超出图像范围。
- 参数越界或类型错误。

### 7.3 自动调参

当前自动调参策略以只读策略查看和部分建议能力为主，完整任务入口、状态展示和结果应用流程尚未完全产品化。

使用建议：

- 可查看策略理解系统支持的调参方向。
- 不要把自动调参输出直接当最终现场参数。
- 对关键参数保留人工确认，例如模型路径、业务标签顺序、ExpectedLabels、ExpectedCount。

## 8. AI 流程生成

### 8.1 配置 AI 模型

进入“设置 / AI 模型”后，可管理多模型配置。

常见字段：

| 字段 | 说明 |
|---|---|
| 名称 | 本地显示别名 |
| Provider | 模型提供方 |
| Model | 模型名称 |
| Base URL | API 地址 |
| API Key | 密钥，后端不回显真实值 |
| Timeout | 请求超时 |
| Reasoning | 推理能力配置 |
| RoleBindings | 模型用途绑定 |

操作步骤：

1. 新建模型配置。
2. 填写 Provider、Model、Base URL 和 API Key。
3. 保存。
4. 点击测试连接。
5. 测试成功后设为激活模型。

安全说明：

- API Key 不应写入项目流程或运行包。
- 导出 Runtime Package 时，疑似密钥、token、password、credential 字段会被阻止。
- 不要把真实密钥提交到仓库。

### 8.2 使用 AI 生成流程

使用步骤：

1. 打开目标项目。
2. 进入 AI 面板。
3. 用自然语言描述检测目标、输入图像、输出结果和现场限制。
4. 根据系统澄清问题补充信息。
5. 生成流程后检查节点、连线和参数。
6. 用样本图做节点预览和完整检测。
7. 人工确认后保存流程。

提示词建议：

- 明确检测对象，例如“端子线序”“螺钉缺失”“标签 OCR”。
- 明确输入来源，例如“本地图像”“相机实时采集”“连续视频流”。
- 明确 OK/NG 判定规则，例如“红黄蓝绿顺序必须一致”。
- 明确输出方式，例如“保存 JSON”“写 PLC”“生成结果记录”。
- 明确限制，例如“不能使用未接入的 MQTT”“模型路径需手动确认”。

### 8.3 AI 生成后的人工检查

AI 生成不是最终交付。保存前必须检查：

- 是否使用了真实存在的算子。
- 是否存在 placeholder 参数。
- 端口连线是否符合数据类型。
- 模型路径、标签路径是否真实存在。
- ROI 是否覆盖目标区域。
- 阈值和置信度是否符合样本验证结果。
- ResultOutput 是否输出了现场需要的字段。

## 9. 检测执行

### 9.1 单次检测

单次检测适合调试、演示和样本验证。

步骤：

1. 打开项目。
2. 确认流程已保存。
3. 准备输入图像或相机配置。
4. 点击执行单次检测。
5. 查看执行状态、耗时、OK/NG、诊断信息和输出图。
6. 若失败，回到流程编辑调整参数或连线。

### 9.2 连续检测

连续检测适合模拟现场运行。

步骤：

1. 配置图像来源或相机。
2. 确认触发方式。
3. 点击开始连续检测。
4. 观察实时结果、吞吐、丢帧、错误和结果历史。
5. 需要停止时点击停止。

注意事项：

- 连续检测时优先保护主检测路径。
- 高频检测下应关注 dropped frames、backpressure 和内存。
- 对真实现场使用，建议先做短时运行，再做长时间稳定性验证。

### 9.3 无触发信号的视频流检测

对于没有光电或 PLC 触发的输送线，可使用 `FrameChangeTrigger`。

推荐流程：

```text
ImageAcquisition(TriggerMode=Continuous)
-> FrameChangeTrigger
-> DeepLearning
-> BoxFilter(FilterMode=Region)
-> BoxNms
-> DetectionSequenceJudge
-> ResultOutput
```

调参顺序：

1. 先设置 `FrameChangeTrigger.RoiX/Y/W/H`，覆盖端子到料区域。
2. 调整 `PixelThreshold`，过滤反光和背景抖动。
3. 调整 `MinChangeRatio` 和 `MinChangePixels`，控制触发灵敏度。
4. 调整 `CooldownMs`，避免同一工件重复触发。
5. 再调 `DeepLearning`、`BoxFilter`、`BoxNms` 和线序判定。

## 10. 结果查看与分析

### 10.1 检测历史

结果页可查看项目检测历史。常见字段包括：

- 检测时间。
- 项目 ID。
- OK/NG/Error。
- 处理耗时。
- 置信度。
- 缺陷数量。
- 诊断信息。

### 10.2 统计、缺陷分布和趋势

当前后端已提供基础分析接口：

- `/api/analysis/statistics/{projectId}`
- `/api/analysis/defect-distribution/{projectId}`
- `/api/analysis/trend/{projectId}`
- `/api/analysis/report/{projectId}`

使用建议：

- 优先查看真实检测历史生成的统计。
- 当样本量很少时，不要过度解释趋势图。
- 对质量评审，应导出报告和原始样本记录一起留存。

### 10.3 高级分析边界

当前高级 CPK、MTBF、缺陷聚类、PDF 深度报告、图片打包等能力仍未完全接入。界面显示“暂无数据 / 未接入”时，表示当前版本不能把这些指标作为正式质量分析输出。

## 11. 设置中心

### 11.1 常规设置

常规设置包括：

- 软件标题。
- 主题。
- 存储路径。
- 数据保留策略。
- 部分运行参数。

当前边界：

- 目录选择器暂未接入执行链路，仍以手填路径并保存配置为主。
- 过期文件即时清理动作暂未开放，当前仅保存清理策略。

### 11.2 主题设置

主题更新走独立接口，避免保存整份配置导致并发覆盖。修改后通常会立即体现在界面上。

### 11.3 恢复默认设置

“恢复默认设置”已接入真实接口，会同时重置系统配置和 AI 模型配置。执行前请确认：

- 当前 AI 模型配置是否已备份。
- 相机、PLC、存储路径等配置是否需要保留。
- 是否会影响现场联调。

该操作建议仅管理员执行。

## 12. 相机管理

### 12.1 搜索相机

相机管理支持：

- 搜索所有可用相机。
- 仅搜索华睿相机。
- 仅搜索海康相机。
- 查看已绑定相机。

步骤：

1. 进入“设置 / 相机管理”。
2. 点击发现设备。
3. 查看设备 ID、厂商、型号、名称等信息。
4. 将相机绑定到业务用途或流程节点。
5. 保存绑定。

### 12.2 软触发拍照

软触发适合调试单帧采集。

步骤：

1. 确认相机在线。
2. 确认相机绑定。
3. 点击软触发采集。
4. 查看预览帧。

### 12.3 连续预览

连续预览适合对焦、取景、ROI 调整。

步骤：

1. 启动连续预览 session。
2. 查看帧图像。
3. 调整相机位置、曝光或 ROI。
4. 停止预览。

注意事项：

- 连续预览不要长时间占用现场相机。
- 预览失败时检查相机驱动、占用进程、网络和权限。
- 宽高参数当前部分入口暂未开放编辑，避免误以为已经保存生效。

## 13. PLC 与触发输入

### 13.1 PLC 配置

设置页支持 PLC 配置和变量映射。当前涉及协议包括：

- Modbus。
- Siemens S7。
- Mitsubishi MC。
- Omron FINS。

配置内容通常包括：

- 协议。
- IP 地址。
- 端口。
- 站号或设备参数。
- 变量名。
- 地址。
- 数据类型。
- 描述。

步骤：

1. 进入“设置 / PLC”。
2. 选择协议 profile。
3. 填写连接参数。
4. 配置变量映射。
5. 点击测试连接。
6. 保存配置。

### 13.2 变量映射

变量映射用于把流程结果写到 PLC 或从 PLC 读取触发/状态。

建议：

- 变量名保持稳定，不要频繁改名。
- 地址格式必须符合协议，例如 S7 的 `DB1.DBX0.0`、MC 的 `D100`、FINS 的 `DM100`。
- 每次修改映射后运行一次 PLC regression 或现场点位测试。

### 13.3 回车/光电触发输入学习

触发输入支持诊断和学习设备。适用于把外部回车类设备映射为触发信号的场景。

步骤：

1. 进入触发输入设置。
2. 查看诊断状态。
3. 点击学习设备。
4. 操作目标输入设备。
5. 确认系统识别到设备。

## 14. Runtime Package 导出

### 14.1 什么时候导出 Runtime Package

以下场景应导出 Runtime Package：

- 准备把项目部署到 Station。
- 需要冻结当前流程版本。
- 需要给现场交付可加载运行包。
- 需要保留 flow hash、package ID 和现场参数 schema。

普通项目导出不等同 Runtime Package。

### 14.2 导出步骤

1. 打开并保存目标项目。
2. 确认流程能在 Studio 内单次检测通过。
3. 检查模型、标签、标定文件等资源路径。
4. 点击 Runtime Package 导出。
5. 选择受控导出目录或使用默认目录。
6. 等待导出完成。
7. 查看导出结果中的 package ID、flow hash、validation report 和 README。

### 14.3 导出前校验

导出会检查：

- 项目是否包含可执行 flow。
- 是否至少有一个算子。
- 参数是否合法。
- 资源文件或目录是否存在。
- 是否包含疑似密钥、token、password、credential。
- 导出目录是否在受控范围内。

若导出失败，请根据错误提示修复，不要绕过校验。

### 14.4 导出目录边界

当前导出目录受控，默认允许：

- Studio 默认运行包目录。
- 仓库 `.tmp/publish-check/`。
- 系统临时目录。
- 环境变量 `CV_RUNTIME_EXPORT_ALLOWED_ROOTS` 配置的白名单目录。

不要把运行包导出到不受控的系统目录或仓库根目录临时文件夹。

## 15. Station 现场端

### 15.1 Station 同步设计

Station 同步是 opt-in。启用时需要：

- Studio Hub URL。
- Shared Token。
- Station 身份信息。
- 本地 spool 目录。

Station 优先保证本地检测路径，不应因为 Studio 离线而阻塞检测主流程。

### 15.2 Station Monitor

在 Studio 的 Station 视图中可查看：

- 站点列表。
- 在线状态。
- Runtime 状态。
- 当前包。
- 最近结果。
- 健康快照。
- 日志。
- 命令历史。
- 审计记录。

### 15.3 Station 结果摘要

Station 向 Studio 推送的是结果摘要，不传输大图像文件。摘要包含：

- Station ID。
- Run ID。
- Package ID。
- Flow hash。
- OK/NG/Error。
- 耗时。
- 诊断码。
- 时间戳。

### 15.4 Station 健康状态

健康状态包含：

- Runtime state。
- 进程内存。
- 磁盘空间。
- Spool pending count。
- Spool bytes。
- Camera status summary。
- PLC status summary。
- Backpressure / dropped result summaries。

如果看到 `StationResultBackpressure`，说明结果摘要出站队列或本地 spool 出现压力，需要检查 Studio 连接、网络、队列容量和磁盘。

### 15.5 命令和部署包

管理员可在 Studio 下发：

- Ping。
- 部署运行包。
- 其他 Station command。

部署包流程：

1. 确认运行包已生成并登记。
2. 在 Station Monitor 中选择目标站点。
3. 选择 package。
4. 下发 deploy-package 命令。
5. Station 拉取包并加载。
6. 查看命令结果、日志和健康状态。

### 15.6 断网和重放

Station 结果摘要会先进入本地 spool。Studio 暂时不可用时，Station 应继续本地检测并积累待同步摘要。恢复连接后再推送。

现场联调建议验证：

- Studio 离线时检测不中断。
- 恢复连接后 spool 可回放。
- spool 超限时有丢弃范围和健康提示。
- 命令下发失败有审计记录。

## 16. 线序检测场景包

线序检测场景包位于：

```text
线序检测/scenario-package-wire-sequence/
```

目录约定：

| 目录/文件 | 用途 |
|---|---|
| `manifest.json` | 当前活动包 manifest |
| `versions/` | 不可变版本发布记录 |
| `template/` | 流程模板 |
| `rules/` | 线序规则和 NG 原因 |
| `labels/` | 模型类别顺序 |
| `models/` | 模型说明，私有模型默认不入仓库 |
| `samples/` | 样本目录契约和 metadata 示例 |
| `faq/` | 场景知识和排障 |

基线流程：

```text
ImageAcquisition -> DeepLearning(OutputFormat=EndToEndNms) -> DetectionSequenceJudge -> ResultOutput
```

视频流流程：

```text
ImageAcquisition(TriggerMode=Continuous) -> FrameChangeTrigger -> DeepLearning(OutputFormat=EndToEndNms) -> DetectionSequenceJudge -> ResultOutput
```

现场交付前必须确认：

- ONNX 模型文件已就位。
- labels 顺序与模型 metadata 对齐。
- expected sequence 与业务检测顺序对齐。
- ROI 参数已按现场图像调整。
- OK/NG 样本已验证。
- 运行包 manifest 包含正确 hash 和版本。

## 17. OperatorLibrary 使用

`Acme.OperatorLibrary` 是可独立打包的算子 NuGet 项目，用于把 ClearVision 算子能力以包形式交付给其他宿主。

常用命令：

```powershell
dotnet build .\Acme.OperatorLibrary\Acme.OperatorLibrary.csproj --configuration Release
& ".\Acme.OperatorLibrary\pack.ps1" -Configuration Release -RunSmokeTest
```

注意：

- OperatorLibrary public catalog 与 Studio 正式算子目录不完全等同。
- 部分内部算子不会进入 NuGet public module catalog。
- 包级 smoke 只证明包可被消费和代表性路径可运行，不等同所有算子现场验收。

## 19. 常见问题

### 19.1 前端提示连接不到后端 API

检查：

- Desktop 进程是否正常启动。
- 本地端口是否被占用。
- WebView2 Runtime 是否安装。
- 前端是否保存了旧端口。
- 防火墙或代理是否拦截本地访问。

### 19.2 单次检测失败

常见原因：

- 流程未保存。
- 算子必填输入未连接。
- 图像为空。
- 模型路径不存在。
- ROI 无效。
- 参数越界。
- 上游输出类型和下游输入类型不匹配。

### 19.3 AI 生成流程不能直接跑

检查：

- AI 是否生成了真实存在的算子。
- 是否遗漏模型、标签、ROI、ExpectedLabels 等人工确认项。
- 是否出现 placeholder 参数。
- 是否存在无法解析或验证失败的 JSON。
- 是否需要 manual retry 或重新澄清需求。

### 19.4 Station 看不到结果

检查：

- Station sync 是否启用。
- StudioHubUrl 和 SharedToken 是否配置。
- Station 是否在线。
- 本地 spool 是否有 pending。
- Studio 端 Station Monitor 是否连接 SSE。
- 是否有 backpressure 或 dropped result summary。

### 19.5 PLC 连接失败

检查：

- 协议是否正确。
- IP、端口、站号是否正确。
- PLC 是否允许当前 PC 访问。
- 地址格式是否符合协议。
- 虚拟 PLC 或真实 PLC 是否启动。
- 防火墙是否阻断。

### 19.6 结果统计看起来不准确

检查：

- 项目 ID 是否正确。
- 检测历史数量是否足够。
- 时间范围是否正确。
- 是否混入调试样本。
- 是否存在错误结果或未持久化结果。
- 高级分析是否仍处于未接入状态。
