# 文档治理标准

本标准用于约束 ClearVision 项目文档的存放位置、生命周期、命名、索引和生成物同步规则。目标是让研发、测试、审计、发布和面试资产都能找到唯一入口，并能判断一份文档当前是否仍可执行。

## 单一事实源

| 领域 | 正式入口 | 镜像或历史入口 | 维护规则 |
|---|---|---|---|
| 项目总览与导航 | `docs/README.md`、`docs/导航.md` | 根 `README.md` 只保留精简入口 | 新增长期文档后必须补入口链接 |
| 当前计划 | `docs/进行中/当前计划/` | `docs/进行中/未闭环事项/`、`docs/进行中/待复核/` | 同一主题只保留一个当前执行入口 |
| 历史计划与闭环材料 | `docs/归档/` | 历史快照内旧链接允许保留 | 关闭计划先写闭环说明，再迁入归档 |
| 算子名片与算子目录 | `docs/算子资料/` | `docs/operators/`、根 `算子资料/` | 以 `docs/算子资料/` 为准，镜像由生成器同步 |
| 审计资料 | `docs/审计资料/` | 外部审计原始材料作为快照 | 审计结论必须保留证据路径和复现入口 |
| 长期规范、指南、手册 | `docs/参考资料/` | 无 | 只有稳定结论沉淀到这里 |
| 模板 | `docs/模板/` | 无 | 新计划、任务、闭环记录优先套模板 |

## 文档状态

| `status` | 含义 | 推荐目录 | 退出条件 |
|---|---|---|---|
| `active` | 当前仍在执行或维护 | `docs/进行中/`、活跃标准/手册 | 完成、替代或废弃后迁出 |
| `needs-review` | 待复核，不能直接对外引用为结论 | `docs/进行中/待复核/` | 复核通过转正，复核失败归档或关闭 |
| `closed` | 已完成并有闭环说明 | `docs/归档/已关闭事项/` | 不再修改正文，只能新增勘误 |
| `archived` | 历史参考或旧版本资料 | `docs/归档/历史资料/`、`docs/归档/历史归档/` | 如需重新启用，新建 active 文档并引用旧文 |
| `deprecated` | 已被新文档替代，但旧链接仍需保留 | `docs/归档/过期计划/` | 新入口稳定后仅保留说明和跳转 |
| `snapshot` | 外部审计、访谈、PDF 转写等原始快照 | `docs/审计资料/外部审计/`、`tmp/` 外部导入区 | 不改写原始语境，另建报告承接结论 |

## 文档类型

常用 `doc_type` 取值如下：

| `doc_type` | 用途 |
|---|---|
| `index` | 目录、导航、索引 |
| `plan` | 可执行计划 |
| `task-list` | TODO、缺陷池、滚动看板 |
| `audit` | 审计过程、审计结论、复核记录 |
| `report` | 对外或阶段性报告 |
| `standard` | 长期约束规则 |
| `guide` | 指南、教程、操作说明 |
| `manual` | 手册、总览型长期资料 |
| `template` | 可复制模板 |
| `record` | 会议纪要、台账、证据登记 |
| `snapshot` | 原始快照或外部材料 |

## 生命周期

1. 创建：新计划放入 `docs/进行中/当前计划/`，新排查放入 `docs/进行中/未闭环事项/`，不确定结论放入 `docs/进行中/待复核/`。
2. 执行：每份 active 文档必须能回答目标、范围、当前状态、下一步、验证证据和完成标准。
3. 复核：重要结论进入 `docs/审计资料/` 或 `docs/参考资料/` 前，必须补齐证据路径、测试入口或可复现步骤。
4. 关闭：关闭计划时新增闭环说明，记录完成项、验证方式、遗留边界和后续入口。
5. 归档：归档文件保留历史语境，不批量改写旧路径；需要重新启用时，新建 active 文档引用旧文。

## 命名与元数据

- 文件名优先使用 `主题-YYYY-MM-DD.md`，长期稳定入口使用 `README.md`、`导航.md`、`索引.md`。
- 周期性审计文件使用稳定前缀，例如 `Week5-审计台账.md`、`Week5-已升级证据链.md`。
- 计划、审计、报告、索引类文档建议保留 YAML front matter：

```yaml
---
title: "文档标题"
doc_type: "plan"
status: "active"
topic: "主题"
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
---
```

## 生成物与镜像

- 算子正式文档以 `docs/算子资料/` 为单一事实源。
- `docs/operators/` 是英文路径兼容镜像，根 `算子资料/` 是历史兼容镜像。
- 生成器入口为 `scripts/OperatorDocGenerator/OperatorDocGenerator.csproj`。后续生成必须同步 `docs/算子资料/`、`docs/operators/`、`docs/CATALOG.md`、`docs/OPERATOR_CATALOG.md` 和根 `算子资料/`。
- 不直接手改镜像文件；确需临时修复时，同步回正式入口或生成器。

## 评审清单

- 是否能从 `docs/README.md` 或 `docs/导航.md` 找到入口。
- 是否明确 `status`，且目录位置与状态一致。
- 是否存在同一主题的多个 active 入口。
- 是否引用了当前事实源，而不是旧镜像或历史快照。
- 是否包含证据路径、测试入口、报告 ID 或可复现步骤。
- 是否需要归档、关闭、转正或合并。
