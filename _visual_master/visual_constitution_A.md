# ClearVision Visual Constitution A

Option: `A - Precision Workstation`  
Scope: Visual reference images only. This document does not authorize frontend implementation.

## Product Authority

The current ClearVision UI, current code, and current contracts are the sole authority for routes, navigation, controls, fields, tabs, panels, actions, states, and business data. Option A may change layout proportion, typography, spacing, surfaces, borders, icon treatment, and visual emphasis. It may not add, remove, rename, or reinterpret a capability.

Generated copy and numbers are not authoritative. The target is a reconstruction reference for visual language only.

## Design Character

Option A treats ClearVision as a precision CAD/IDE-class engineering workstation:

- very high order and scan efficiency;
- compact information density without crowding;
- crisp hierarchy and deterministic geometry;
- quiet, technical, and comfortable for long sessions;
- strongest emphasis on canvas, evidence, inspector, and command context.

## System Language

- Stable graphite application frame with cool light work surfaces.
- Crisp `1 px` dividers carry most hierarchy; elevation is rare.
- Corners stay in the `2-4 px` range.
- Compact `28-32 px` controls, `32-38 px` rows, and a strict `4/8 px` rhythm.
- Typography is Windows-native, compact, neutral, and optimized for numeric alignment.
- ClearVision cinnabar `#b6453c` is reserved for selection/brand emphasis.
- Action blue `#166f9f`; OK `#16866f`; NG `#d12f3f`; warning `#9b6a13`.
- Status always uses icon/label plus color.

## Composition

- Navigation, context bar, command bar, work surface, inspector, and evidence regions remain explicit.
- Toolbars read as engineering commands, not consumer-app button groups.
- Tables use strong alignment, compact rows, restrained row actions, and stable column geometry.
- Forms group by engineering dependency and keep labels, units, values, status, and diagnostics close.
- Empty/error/running/result states preserve the parent page geometry.
- Dialogs remain scoped overlays with a clear exit and consequence boundary.

## Prohibitions

- No new buttons, tabs, modules, navigation, telemetry, dashboards, charts, cards, shortcuts, AI abilities, device abilities, workflow abilities, or data.
- No generic SaaS dashboard, nested card mosaic, oversized KPI tiles, poster headings, pills, glass, glow, gradient decoration, or concept-art framing.
- No invented logo, watermark, third-party mark, or additional brand treatment.
- No visual flourish that weakens implementation feasibility or engineering scan speed.

## Master Chain

`A_FLOW_MASTER -> A_AI_MASTER -> A_SETTINGS_MASTER`

All Option A local screens may reference only these Option A Masters. A Master contributes style only; the current screenshot remains the functional authority.
